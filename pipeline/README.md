# 스토리닷 파이프라인

아동 애니메이션 한 편을 넣으면 **아이가 방해받았다고 느끼지 않을 순간**과, 그 순간에 낼
**근거 있는 활동**을 뽑아 `activity_plan.json` 으로 내놓는다. 재생 중에는 LLM을 호출하지 않는다.

```bash
./setup.sh                                      # ffmpeg · whisper.cpp · 모델 2GB (최초 1회)
python3 storydot.py ~/Downloads/타요1화.mp4      # ① 개입지점 + 증거번들  → work/타요1화_plan.json
python3 generate.py work/타요1화_plan.json        # ② 활동 생성·검증      → work/타요1화_cards.json
python3 generate3.py 타요1화                     # ③ 마무리 활동         → work/타요1화_final.json
```

결과를 아이가 보는 앱까지 잇는 법은 [앱에 붙이기](#앱에-붙이기).

활동은 **2019 개정 누리과정** 5개 영역에 매핑되어 생성된다. 생성자와 검증자는
`claude` CLI **별도 프로세스 2개**로 띄운다 — 같은 문맥을 공유하면 검증이 아니라 추인이 된다.

파이썬 외부 패키지가 **0개**다. 표준 라이브러리 + `ffmpeg` + `whisper-cli` 만 쓴다.
API 키가 필요 없고 종량 과금도 없다.

---

## 이 파이프라인이 푸는 두 문제

**1. 언제 끼어들 것인가.** 아무 데서나 멈추면 아이는 끊겼다고 느낀다.
**2. 무엇을 물을 것인가.** 근거 없는 퀴즈는 아이에게 틀린 것을 가르친다.

둘 다 순진한 해법이 실측에서 무너졌다. 아래 표가 이 코드의 형태를 결정했다.

| 순진한 가정 | 실측 결과 |
| --- | --- |
| 좋은 모델 하나 쓰면 된다 | `large-v3-turbo` 환각 **23.5%**, `small` 이 **9.1%**. 작은 모델이 2.6배 낫다 |
| VAD로 환각을 없애면 된다 | 환각은 0%가 되지만 **실제 대사 30%가 사라진다** |
| 두 에이전트가 교차검증하면 된다 | 세 패스가 **같은 오답으로 수렴**했다 (`날 수 있겠어` → `날씨 있겠어`) |
| 조용해질 때 끼어들면 된다 | BGM이 안 끊긴다. 762초에 1초 이상 공백이 **16개**, 3분짜리 사막이 두 번 |
| 장면 전환을 임계값으로 잡는다 | 어두운 구간에서 **2컷 vs 실제 39컷** (19배 오차) |
| 오디오로 타이밍을 정하면 된다 | 9개 지점 중 **3개가 동작 한복판** (바느질·점프·기차 주행) |

전체 근거와 재현 명령은 [docs/PIPELINE_PLAN.md](docs/PIPELINE_PLAN.md). 실행하며 뒤집힌
판단 6개는 같은 문서 **부록 B**에 남겨 뒀다.

## 아키텍처

```
영상
 │
 ├─ 오디오 ─┬─ small  -mc 0    기준 타임라인 (재현율 최고)
 │          └─ turbo + VAD     교차검증 앵커 (환각 0%, 재현율 낮음)
 │                  │
 │                  ▼
 │        정본 = 시간축 세그먼트 + 안정 ID (NFC 정규화 1회)
 │        ┌──────────────────────────────────────────────┐
 │        │ high        시리즈 사전 검증 + 내용이 있음    │
 │        │ medium      앵커 일치 OR 앵커가 안 다룸(보류) │
 │        │ low         앵커가 다뤘는데 어긋남 (반증)     │
 │        │ quarantine  환각 탐지 적발 (근거 사용 금지)   │
 │        └──────────────────────────────────────────────┘
 │                  │
 │       ┌──────────┴──────────┐
 │       ▼                     ▼
 │   act 경계 3단 폴백      하드규칙 6개
 │   1 내레이션 종결        · 몰입 전 금지      · 엔딩 이후 금지
 │   2 beats.py 다중신호    · 발화 재개 3초 확보 · 활동 간 최소 간격
 │   3 균등 분할            · 격리 스팬 인접 금지 · 근거 5건 미만이면 안 만듦
 │                                 │
 └─ 화면 ─ motion.py ──────────────┤  컷 ≠ 동작 분리 · 샷 크기(작품별 정규화)
           visual.py ──────────────┤  프레임 4장 + 결정적 색 팔레트
                                   ▼
                        개입지점 + 증거번들
                                   │
                    생성 에이전트 ↔ 검증 에이전트
                                   │
                    activities.py  ← 인용이 원문에 있는가
                    grounding.py   ← 정답이 증거에서 나오는가
                                   ▼
                          activity_plan.json
```

### 모듈

| 파일 | 역할 | 왜 있는가 |
| --- | --- | --- |
| `storydot.py` | 본체. 인제스트 → ASR → 정본 → act → 개입지점 | |
| `beats.py` | 다중 신호 장면 경계 | 내레이터 없는 작품에서 무음 공백만 쓰면 경계에 의미가 없다 |
| `motion.py` | 컷/동작 분리, 샷 크기 | 컷은 멈추기 **좋은** 자리인데 같이 버려졌다 |
| `visual.py` | 프레임 + 색 팔레트 | 대사만으로는 개수·색깔 퀴즈를 못 만든다 |
| `grounding.py` | 정답 근거 검사 | 인용은 진짜인데 정답만 지어낸 카드가 빠져나갔다 |
| `activities.py` | 인용 대조 게이트 | LLM 합의와 무관한 결정적 최후 관문 |
| `generate.py` | 생성↔검증 오케스트레이션 | `claude` CLI 2프로세스로 검증 독립성 확보 |
| `skills/quiz/` | 생성자 계약 | 누리과정 5영역 · 20개 활동 유형 · 연령별 발달 수준 |
| `skills/verify/` | 검증자 계약 | 출제자의 근거 설명을 **받지 않는다** |
| `series/<작품>.json` | 이름·구 사전 | 사람이 한 번 확정. 미확정은 치환하지 않는다 |

각 모듈은 `python3 <파일>.py` 로 자체검사가 돈다. 전부 실제 영상으로 검증한다.

## 핵심 설계 판단 넷

### 1. 침묵은 반박이 아니다

앵커(VAD)는 환각이 0%인 대신 대사의 30%를 버린다. "앵커가 동의해야 신뢰"로 짰더니
티니핑 167개 중 medium이 **3개**로 붕괴하고 개입지점이 0이 됐다. 앵커가 **겹칠 때만**
판정하고, 안 겹치면 판단을 보류하도록 고쳤다. → medium 3 → 154.

### 2. 이름 대표형은 자동으로 못 정한다

자모 유사도로 변이형을 묶는 것까지는 된다. 그런데 빈도로 대표형을 고르면
`크랑 ← {크롱, 클랑}` 이 나온다 — ASR이 크롱을 크랑으로 자주 잘못 듣기 때문에
**오답이 최빈형**이다. 자동 확정은 정답을 오답으로 덮어쓴다.
군집만 제안하고 대표형은 사람이 `series/<작품>.json` 에 한 번 찍는다.
**미확정이면 치환하지 않는다** — 오염보다 무동작이 낫다.

### 3. 절대 임계값은 작품이 바뀌면 무너진다

세 번 같은 실수를 했다.

- 장면 전환 임계 0.35 고정 → 어두운 구간에서 19배 오차
- 클로즈업 판정 `tv < 10` 고정 → 평면 2D 작화(아기상어)가 **전 장면 클로즈업**으로 읽혀 전멸
- 엔딩 경계를 공백 **크기**로 탐색 → 두 번 연속 오검출

전부 작품 안에서 **상대적으로** 재도록 고쳤다. `detail_baseline()` 이 그 예다.

### 4. 게이트는 LLM 판단이 아니다

두 에이전트가 합의해도 아래를 통과해야 카드가 산다. 실패는 재시도가 아니라 **폐기**다.

```
① quote 가 해당 세그먼트 원문에 그대로 있는가     activities.py
② 그 세그먼트 신뢰도가 high/medium 인가           activities.py
③ 스팬이 act 안이고 격리 구간과 안 겹치는가        activities.py
④ answer 가 증거에서 도출 가능한가                grounding.py
```

실제로 두 종류를 잡았다.

```
[폐기] 개수 세기   인용 불일치 — '친구들이 모여 있어요' 는 전사본에 없다
[폐기] 의성어      정답 '쓱쓱' 이 증거 어디에도 없다 (인용은 진짜였다)
```

| --- | --- | --- | ---: | ---: | --- |
| 타요 | 10:09 | 5 [narration] | 3 | **11** | 셋 다 와이드 정지샷. 개수·색 퀴즈 최적 |
| 뽀로로 | 12:42 | 6 [narration] | 2 | **8** | 11:00 은 와이드 + 열린 질문 직후로 이상적 |
| 아기상어 | 11:28 | 4 [narration] | 1 | **4** | 근거 부족으로 3곳 기각 |
| 티니핑 | 12:58 | 6 [beats] | 1 | **3** | 내레이터 없음. 2:42는 "멈출 자리 없음"으로 기각 |
| 브레드 | 10:54 | 5 [narration] | **0** | — | 대사가 안 쉰다. 억지로 넣지 않고 0을 낸다 |
| **합계** | | | **7** | **26** | 폐기 2 · 게이트 통과율 93% |

**누리과정 영역 분포** — 의사소통 7 · 사회관계 7 · 자연탐구 6 · 예술경험 6
**연령 분포** — 3세 11 · 4세 7 · 5세 8 · **창작형(정답 없음) 7건(27%)**

활동 26건 전수를 사람이 직접 검증했다 (프레임을 열어 직접 세고 인용을 원문과 대조).
화면 근거 카드 8건의 개수·색 판정 **오답 0건**. 상세는 [docs/정성검증.md](docs/정성검증.md).

**0을 내는 것이 정상 동작이다.** 근거가 얇거나 멈출 자리가 없으면 활동을 만들지 않는다.
기각 사유는 전부 `plan.json` 의 `rejected` 에 남는다.

## 알려진 한계

- **티니핑 본편 끝이 `[tail]` 폴백이다.** 5편 중 유일하게 노래 구간도 내레이션도 못 찾았다.
  12:41 개입이 엔딩 크레딧 안일 가능성을 배제하지 못한다.
- **검증자도 LLM이다.** 결정적 게이트가 최후 방어선이지만, 게이트가 못 잡는 유형
  (연령 수준 초과, 오답 모호성)은 검증자 판단에 의존한다.
- **색 팔레트의 바닥은 약 0.5%다.** 작은 사물(상어 눈동자 0.41%)은 `absent` 로 떨어진다.
  `colors`(≥3%, 정답 가능) / `trace`(애매, 눈으로) / `absent`(<0.5%, 오답 보기로 안전)
  3분할이라 **"화면의 빨간 버스가 없다"고 단언하지는 않는다** — 1.48%짜리 버스를
  `absent` 로 판정했던 버그의 흔적이다.
- **용언 활용은 못 잇는다.** `grounding.py` 는 접미사 벗기기 근사라 `찾았어요` ↔ `찾아줬잖아`
  연결에 실패한다. 놓치는 쪽(과폐기)으로 의도적으로 기울였다. `GROUNDED_RATIO` 하나로 조정.
- **브레드류(대사 밀도 높은 작품)는 개입지점이 안 나온다.** 페이드아웃 3초를 못 확보한다.
  `params()` 의 `speech_pad` 를 낮추거나 오디오 덕킹으로 푸는 것이 다음 수순이다.
- **시리즈 사전 부트스트랩 비용.** 신규 시리즈 첫 편은 `proposed` 군집을 사람이 확정해야
  `high` 등급이 나온다. 확정 전에도 파이프라인은 돌지만 신뢰도 상한이 medium 이다.

## 개발 메모

- `work/` 는 캐시다. `*_small.json` / `*_vad.json` 전사본이 있으면 ASR을 다시 안 돌린다.
  전사본을 지우면 재실행 시 다시 받아쓴다 (12분 1편에 M2 Pro 기준 약 3분).
- 커밋된 전사본 JSON은 **회귀 테스트 픽스처**다. 환각율·경계 검출 수치가 여기서 나온다.
- `wav` 와 `models/` 는 용량이 커서 배포본에서 뺐다. `setup.sh` 가 모델을 다시 받는다.

## 앱에 붙이기

파이프라인 결과를 아이가 실제로 보는 화면까지 잇는다. 앱은
[StaryDot](https://github.com/geonoh-nam/StaryDot) `feat/split-frontend-backend` 의 프론트를
가져왔고, 세션 편성은 `curri` 의 스크린타임 편성 알고리즘을 그대로 쓴다.

```
work/<작품>_final.json           generate3.py 의 마무리 활동 (문항 + 근거 프레임)
        │
        ▼  backend/server/tools/seed-from-work.js
    stary.db  ·  media/frame/*.jpg
        │
        ▼  GET /plan?character_id=…&budget_sec=…
   세션 편성  =  영상 → 브레이크 → 영상 → … → 미션 카드
        │        (backend/server/planner/planner.ts — curri)
        ▼
   frontend  (Expo · Package → Watch → Break → Mission → Bye)
```

### 세 줄로 띄우기

```bash
cd backend/server
node tools/seed-from-work.js ../../work --video-dir ~/Downloads   # 파이프라인 결과 → DB
node tools/add-videos.js                                          # inbox/<시리즈>/ 의 영상 → DB
node index.js                                                     # 콘텐츠 서버 :5056
cd ../../frontend && npx expo start                               # 앱
```

원본 mp4 가 없으면 `--placeholder <아무.mp4>` 로 배선만 먼저 볼 수 있다. **길이는
`_plan.json` 의 실측값을 그대로 쓰므로 편성 계산은 진짜고, 재생되는 화면만 대역이다.**

작품 이름과 앱 시리즈를 잇는 표는 `backend/server/work-manifest.json` 하나다. 새 작품이
붙으면 여기 한 줄을 더한다. 이름을 코드가 추측하지 않는다 — 잘못 이어 붙은 영상은
조용히 틀린 시리즈에 들어가고, 그걸 알아채는 사람이 없다.

### 재생목록을 예산에 맞게 채우려면

편성기는 **고른 시리즈 안에서만** 영상을 고른다. 시리즈에 1편뿐이면 예산이 얼마든 재생목록은
1편으로 끝나고, 브레이크는 영상 **사이**에만 붙으므로 문항이 화면에 도달하지 못한다.
문제는 알고리즘이 아니라 후보 수다.

영상은 파이프라인을 안 돌려도 넣을 수 있다. `inbox/<시리즈>/` 에 파일을 두고 실행한다.

```bash
mkdir -p backend/server/inbox/tayo
cp ~/Videos/타요2화.mp4 backend/server/inbox/tayo/
cd backend/server && node tools/add-videos.js
```

문항이 0개인 영상도 편성에 들어간다 — 편성기는 문항이 있는 영상 뒤에만 브레이크를 붙인다.
**영상으로 재생목록을 먼저 채우고 문항은 나중에 얹는** 순서가 성립한다. 나중에 그 영상의
문항을 얹을 때는 `tools/from-storydot.js <video_id> work/<작품>_final.json`.

타요 3편(문항은 1화에만)으로 예산을 바꿔 보면:

| 예산 | 편성 |
| --- | --- |
| 10분 | 6분 + 1분 + 미션 · 총 8분 26초 |
| 20분 | 10분 + **브레이크 2문항** + 6분 + 1분 + 미션 · 총 19분 15초 |
| 30분 | 위와 같음 — 카탈로그가 3편뿐이라 더 못 채운다 |

영상은 길이 내림차순으로 놓인다. 뒤로 갈수록 짧아져 세션이 줄어드는 느낌을 주고, 마지막
영상이 짧아 끝날 때 상실감이 적다.

### 왜 문항이 영상이 끝난 뒤에 있는가

`generate3.py` 는 **영상이 끝난 뒤** 낼 문항을 만든다. 중간 개입을 포기하면 정지점 문제가
통째로 사라지고(발화 밟기 · 위기 절정 · 샷 크기 오판), 대신 커지는 회상 부담은 **문제에
화면을 붙여** 재인으로 바꿔 해결한다.

    "버스가 몇 대였나요?"              12분 전을 기억해야 함
    "이 그림에 버스가 몇 대 있나요?"    눈앞에서 세면 됨 — 3세도 가능

그래서 브레이크 화면은 문항과 근거 프레임을 **반드시 같이** 띄운다. 프레임이 없는 문항은
`toStorydotRow` 가 만들기를 거부한다 — 그림 없는 화면을 내보내는 것보다 문항 하나를 잃는
편이 낫다.

브레이크는 **문항을 가진 영상마다 하나씩** 붙는다. 마지막 영상도 예외가 아니다 — 아이가
마지막으로 본 것을 묻지 않고 넘어가면 그 편은 아무것도 남기지 않는다. 그 뒤에 미션 카드가
온다. 문항이 없는 영상 뒤에는 브레이크를 만들지 않고, 시간 회계도 같은 기준으로 센다.

### 시간 예산

보호자가 정한 하루 총량 안에 영상과 활동이 **전부** 들어간다. 퀴즈도 화면을 보는 시간이다.

```
total(k) = Σ(영상 길이) + (문항 있는 편수) × 40초 + 20초
                          브레이크              미션 카드
```

퀴즈 개수가 영상 개수에 종속되므로 고정 용량 배낭문제가 아니다. `totalSec()` 이 세는
브레이크 수는 `buildPlan()` 이 실제로 만드는 수와 **정확히 같아야** 예산이 어긋나지 않는다. 근거와 알고리즘은
[docs/curri/2026-08-25-screentime-session-planner-design.md](docs/curri/2026-08-25-screentime-session-planner-design.md).

### 접합부 파일

| 파일 | 역할 |
| --- | --- |
| `backend/server/work-manifest.json` | 작품 ↔ 앱 시리즈 매핑. 사람이 한 줄씩 확정 |
| `backend/server/tools/seed-from-work.js` | `work/` 한 폴더 → 라이브러리 · 문항 · 프레임 |
| `backend/server/tools/add-videos.js` | `inbox/<시리즈>/` 의 영상 → 라이브러리 (문항 없이도) |
| `backend/server/activity-payload.js` | `toStorydotRow` — 파이프라인 활동 → 앱 payload |
| `backend/server/planner/planner.ts` | 세션 편성 (curri, 무수정) |
| `backend/server/session.js` | DB ↔ 편성기. 알고리즘의 순수함을 지키는 경계 |
| `frontend/screens/Break.js` | 영상 사이 브레이크 — 프레임 + 문항 |
| `frontend/screens/Mission.js` | 세션 착지점. 화면 밖 미션 카드 |

```bash
node backend/server/test.js                      # 접합부 회귀 (18)
node backend/server/planner/planner.selfcheck.ts # 편성 알고리즘 자체검사
cd frontend && sh scripts/check.sh               # 앱 정적 검사
```

### 지금의 한계

- **파이프라인을 돌린 작품이 시리즈당 1편뿐이다.** 영상 자체는 `add-videos.js` 로 채울 수 있지만
  문항은 파이프라인을 돌린 편에만 있다. 문항 없는 편은 브레이크 없이 지나간다.
- **브레이크 한 번에 두 문항까지만 나간다.** `QUIZ_ITEMS_PER_BREAK = 2` 상한이라 그보다 많이
  만든 편은 나머지가 DB 에 남은 채 안 쓰인다.
- **창의 문항(장면 감상 · 가장 좋았던 장면)은 아직 안 싣는다.** 정답이 없어 4지선다 화면에
  들어가지 않는다. 5건이 여기서 빠진다. `SayIt` 활동에 붙이는 것이 다음 수순이다.
- **영상 중간 개입은 꺼져 있다.** `WatchScreen` 의 `midVideo` 를 켜면 되살아난다. 켜면 실제
  화면 시간이 예산을 넘으므로 `totalSec()` 의 회계를 같이 고쳐야 한다.
