# 스토리닷 — 영상→활동 생성 파이프라인 설계안

> 대상: 아동용 애니메이션 1편을 입력받아, **끊기지 않는 타이밍**에 **할루시네이션 없는** 교육 활동
> (퀴즈·퍼즐·색칠·그리기)을 배치한 실행 계획(JSON)을 산출한다.
>
> 기반 레포: [`bradautomates/claude-video`](https://github.com/bradautomates/claude-video) (`/watch` 스킬)
> — yt-dlp + ffmpeg + Whisper 인제스트 계층을 재사용한다.
>
> 검증 대상: `뽀로로 1화 — 요술 이불` (12:42 / 1920×1080 / 29.97fps / AAC 스테레오 / **자막 트랙 없음**)

---

## 0. 요약 — 실측으로 드러난 것

설계 전에 실제 영상으로 다섯 가지를 측정했다. **네 개가 처음 가정을 뒤집었다.**

| # | 측정한 것 | 결과 | 설계에 미친 영향 |
|---|---|---|---|
| 1 | Whisper `large-v3-turbo` 원본 | **전체 구간의 23.5%가 환각** | 단일 ASR 사용 불가 |
| 2 | 동일 모델 + Silero VAD | 환각 **0.0%**, 그러나 실제 대사 **약 30% 소실** | VAD 단독도 불가 |
| 3 | `small` 모델 교차 | 환각 9.1% — **turbo가 망친 구간을 small이 복원** | 모델 크기 ≠ 정확도 |
| 4 | ffmpeg 장면 전환 (임계 0.35 고정) | 어두운 구간에서 **2컷 vs 실제 39컷 (19배 오차)** | 고정 임계값 사용 불가 |
| 5 | 무음 구간 탐지 | 762초 중 **1초 이상 공백 16개**, 3.5초 이상 **5개** | "조용할 때 끼어들기" 전략 폐기 |

이 다섯 개가 아래 설계의 전부를 결정한다. 나머지는 그 귀결이다.

## 1. 측정 근거 (재현 명령 포함)

### 1.1 ASR 환각 — 23.5%

```bash
ffmpeg -i 뽀로로1화.mp4 -vn -ac 1 -ar 16000 audio.wav
whisper-cli -m ggml-large-v3-turbo.bin -f audio.wav -l ko -oj -of stt_turbo
```

160개 세그먼트 중 13개가 반복 루프 환각. **환각 구간 합계 163초 / 694초 = 23.5%.**

```
[0:57.4→1:14.0] 크랑 크랑 크랑 크랑 크랑 크랑 크랑 크랑 크랑 크랑        (16.6초)
[1:14.0→1:31.8] 크랑 크랑 크랑 크랑 크랑 크랑 크랑 크랑 크랑 크랑 크랑 크랑 크랑 (17.8초)
[4:56.6→4:56.6] 크라! 크라! 크라! … ×71                                (지속시간 0초)
[6:03.2→6:33.2] 크롱 크롱 크롱 … ×73                                    (30.0초)
[12:29.8→12:29.8] 뽀롱, 뽀롱, … ×39                                     (지속시간 0초)
```

두 가지 실패 유형이 섞여 있다.

- **반복 루프** — BGM만 있고 발화가 없는 구간에서 Whisper가 직전 토큰을 무한 반복한다.
- **타임스탬프 붕괴** — `4:56.62→4:56.62`, `12:29.76→12:29.76`처럼 **지속시간이 0인 세그먼트**.
  환각 구간에서는 텍스트만이 아니라 **시간 정보 자체가 무효**다. 활동 배치는 시간에 의존하므로 이건 치명적이다.

BGM이 원인이라는 근거: 환각 3대 구간(0:57–1:52 취침·BGM, 4:56–5:27 눈보라, 6:03–6:33 동굴)은
모두 **대사가 없고 음악만 흐르는 구간**이다.

### 1.2 VAD는 환각을 지우지만 대사도 지운다

```bash
whisper-cli -m ggml-large-v3-turbo.bin -f audio.wav -l ko \
  --vad --vad-model ggml-silero-v5.1.2.bin --vad-threshold 0.5 -oj -of stt_vad
```

| | 세그먼트 | 환각 |
|---|---|---|
| turbo (VAD 없음) | 160 | 23.5% |
| turbo + VAD | 70 | **0.0%** |

환각은 완전히 사라졌다. 그런데 세그먼트가 160 → 70으로 줄었고, 사라진 것 중에 진짜가 많다.

```
[0:48.89→2:29.85] 이불이 웃겨요.              ← 101초를 네 단어로 압축
[4:07.17→4:54.17] 그리고 먼 숲으로 날아갔습니다. ← 47초 압축, 그 사이 대사 전멸
[9:21.89→9:56.29] 아직 자고 있었구나.          ← 34초 압축
```

11:01 이후 **엔딩 주제가 전체가 통째로 소실**. 원본에서는 정상 인식됐던 구간이다.

동시에 VAD판이 **더 정확해진 것도 있다**: `솜이브 → 솜이불`, `요수리불 → 요술이불`.
그리고 **새로 틀린 것도 있다**: `모두 잠든 밤 → 모두 잠든 팝`, `어두워서 → 더워서`, `낚시하러 → 취하러`.

→ **정밀도와 재현율이 정확히 상충한다. 둘 중 하나를 고르는 문제가 아니다.**

### 1.3 큰 모델이 더 낫지 않다 — 이게 핵심이다

| 실행 | 세그먼트 | 환각 |
|---|---|---|
| `large-v3-turbo` | 160 | 23.5% |
| `large-v3-turbo` + VAD | 70 | 0.0% |
| **`small`** | 197 | **9.1%** |

`small`이 `large-v3-turbo`보다 환각이 **2.6배 적다.**

6:03–6:33 구간 — turbo가 "크롱" 73회로 30초를 통째로 날린 곳:

```
small 모델이 복원한 실제 내용
  6:16.2  크롱!
  6:17.2  뭐해?
  6:18.2  예쁜 실이네
  6:20.2  이걸로 이불을 꿰매주자
  6:25.7  뽀로로와 크롱은 실을 따라서
  6:28.2  동굴 깊숙이 들어갔습니다
```

**이 구간은 줄거리의 전환점이다.** 실을 발견하고 동굴로 들어가는 장면 — 6:40부터 시작되는
곰인형 에피소드(이 화의 교훈 핵심)의 도입부다. turbo만 썼으면 이 act 전체가 증발한다.

→ **"제일 좋은 모델 하나 쓰면 된다"가 성립하지 않는다. 오류가 모델마다 다른 곳에서 난다.**
이게 합의(consensus) 설계의 근거다.

### 1.4 시각 장면 전환 — 고정 임계값은 19배 틀린다

```bash
# 전체, 임계 0.35
ffmpeg -i 뽀로로1화.mp4 -vf "select='gt(scene,0.35)',metadata=print" -an -f null -
```

전체 **112컷 / 762초** — 평균 6.8초에 한 컷. 그런데 구간별로 보면:

| 구간 (4:44–6:40, 야간 눈보라) | 검출 컷 |
|---|---|
| 임계 0.35 | **2** |
| 임계 0.10 | **39** |

임계 0.35는 이 구간을 **"115초 동안 컷이 없는 정지 화면"**으로 보고한다. 실제로는 39번 전환한다.
어둡고 대비가 낮은 장면에서 프레임 간 차이가 임계값을 넘지 못하기 때문이다.

→ 이 오류의 방향이 나쁘다. **가장 정신없는 구간을 "가장 조용한 구간"으로 오인**한다.
그대로 쓰면 눈보라 한복판에서 퀴즈를 띄운다.

### 1.5 무음 기반 타이밍은 성립하지 않는다

```bash
ffmpeg -i audio.wav -af "silencedetect=noise=-32dB:d=0.6" -f null -   # → 13개
ffmpeg -i audio.wav -af "silencedetect=noise=-45dB:d=0.3" -f null -   # → 8개
```

임계를 아무리 풀어도 762초에서 무음이 10개 안팎이다. **BGM이 끊기지 않기 때문이다**
(Integrated −18.4 LUFS, LRA low −29.0 LUFS — 바닥이 무음이 아니라 음악이다).

발화 공백(turbo ∪ small 커버리지의 빈 곳)으로 다시 계산해도:

```
1초 이상 공백 16개 · 3.5초 이상 5개 · 최대 5.7초(타이틀 카드)
분포:  0:55–3:38 (2분 43초) 공백 1개
       3:38–6:41 (3분 03초) 공백 0개
       6:41–9:17 (2분 36초) 공백 11개   ← 16개 중 11개가 여기 몰려 있다
```

→ 공백은 **개수도 부족하고 분포도 최악**이다. 3분짜리 사막이 두 번 나온다.
"조용해지면 끼어든다"로는 12분 영상에 활동 2개도 못 놓는다.

## 2. 그래서 무엇이 진짜 문제인가

원래 요구는 *"2개 에이전트가 교차검증해서 할루시네이션을 없앤다"* 였다.
**필요하지만 충분하지 않다.** 측정 결과가 그 이유를 보여준다.

두 에이전트에게 **같은 전사본**을 주고 서로 검증시키면, 둘 다 `6:03–6:33 = "크롱 크롱 크롱…"`을
사실로 받아들인다. 오류가 입력에 있으면 **두 검증자의 오류는 독립이 아니라 완전 상관**이다.
프롬프트를 아무리 다르게 짜도 같은 거짓말을 공유한다.

> **교차검증의 독립성은 프롬프트가 아니라 증거 채널에서 나와야 한다.**

그래서 검증을 두 층으로 나눈다.

| 층 | 무엇을 교차하는가 | 독립성의 출처 |
|---|---|---|
| **하층 — ASR 합의** | 서로 다른 모델·VAD 설정의 전사본 3개 | 모델별로 **다른 곳에서** 틀린다 (§1.3 실측) |
| **상층 — 활동 검증** | 생성 에이전트 ↔ 검증 에이전트 | 청각 증거 + **시각 증거**(프레임) |

그리고 마지막 관문은 LLM 판단이 아니라 **결정적 문자열 대조**로 닫는다 (§3.6).

## 3. 파이프라인

```
   영상
    │
 ┌──▼──────────────────────────────────────────────────┐
 │ S0  인제스트           claude-video 재사용          │
 │     ffprobe · 오디오 16k 모노 · 프레임 추출          │
 └──┬───────────────────────────────┬──────────────────┘
    │ audio.wav                     │ frames/*.jpg
 ┌──▼───────────────────────┐  ┌────▼─────────────────┐
 │ S1  ASR 3중 합의         │  │ S3  시각 접지        │
 │  A: turbo    (재현율)    │  │  적응형 장면 검출     │
 │  B: small    (독립 오류)  │  │  act별 키프레임 캡션  │
 │  C: turbo+VAD (정밀도)   │  │                      │
 │  → 세그먼트별 confidence │  │  ← 독립 증거 채널     │
 └──┬───────────────────────┘  └────┬─────────────────┘
    │                                │
 ┌──▼───────────────────────┐        │
 │ S2  시리즈 사전 교정     │        │
 │  크랑/크라/클랑 → 크롱   │        │
 └──┬───────────────────────┘        │
    │                                │
 ┌──▼────────────────────────────────▼─────────────────┐
 │ S4  act 분할 + 개입지점 스코어링                     │
 │     내레이션 종료 · 발화 공백 · 컷 밀도 · BGM 전환   │
 └──┬──────────────────────────────────────────────────┘
    │  act별 증거 번들 (high/medium 스팬 + 프레임)
 ┌──▼──────────────────────────────────────────────────┐
 │ S5  생성 ↔ 검증 (2 에이전트)                        │
 │     → S6  결정적 스팬 대조 게이트                    │

    │

```

### S0 — 인제스트 (재사용)

`claude-video`에서 **그대로 쓴다**: `download.py`(yt-dlp), `frames.py`(auto-fps·dedup·장면 후보).
`frames.py`의 프레임 예산·중복 제거 로직은 검증된 자산이다.

**교체한다**: `transcribe.py` / `whisper.py`. 둘 다 **Groq/OpenAI API 전용**이라
키가 필요하고 다중 패스에 비용이 곱해진다. `whisper.cpp` 로컬 실행으로 대체한다
(M2 Pro / Metal 기준 12분 오디오에 turbo 약 2분, small 약 33초, **비용 0, 키 0개**).

### S1 — ASR 3중 합의

3회 독립 실행 → 세그먼트별 신뢰도 산출.

**환각 탐지기** (프로토타입 검증 완료, §1.1의 13건을 전부 잡아냄):

```python
def is_hallucinated(text, dur):
    toks = re.findall(r'[가-힣]+', text)
    if not toks: return False
    n = Counter(toks).most_common(1)[0][1]
    return (n >= 5 and n/len(toks) > 0.6)   # 반복 루프
        or dur <= 0.01                       # 타임스탬프 붕괴
        or len(text)/dur > 12                # 물리적으로 불가능한 발화 속도
```

**신뢰도 등급**

| 등급 | 조건 | 활동 근거로 사용 |
|---|---|---|
| `high` | 3개 패스 중 3개 일치 (정규화 후) | ✅ |
| `medium` | 2개 일치 | ✅ |
| `low` | 불일치 | ❌ 타이밍 신호로만 사용 |
| `quarantine` | 환각 탐지기 적발 | ❌ **완전 배제** |

`low`/`quarantine`도 버리지 않는다 — **"여기서 뭔가 일어나고 있다"**는 타이밍 정보는
여전히 유효하다. 다만 **문제를 출제할 근거로는 절대 쓰지 않는다.**

### S2 — 시리즈 사전 교정

가장 싸고 효과가 큰 단계. 등장인물 이름은 **닫힌 집합**이라 결정적으로 고칠 수 있다.

| 오인식 | 교정 | 관측 위치 |
|---|---|---|
| 크랑 · 크라 · 클랑 | **크롱** | 전편에 걸쳐 |
| 보로로 · 뽀롱 | **뽀로로** | 11:04, 12:29 |
| 요수리불 | **요술 이불** | 10:20, 10:25 |
| 꿀매줄게 | **꿰매줄게** | 5:35 |
| 솜이브 | **솜이불** | 8:32 |
| **날씨 있겠어** | **날 수 있겠어** | 7:42, 7:50 |
| 그라운 | 그럼 | 5:45 |

`날씨 있겠어 → 날 수 있겠어`가 왜 중요한지 — 이건 단순 오타가 아니라 **의미가 뒤집힌다.**
"이제 날 수 있겠어?"(이불 수선 완료, 다시 날 수 있는가)가 "날씨"에 관한 질문이 되면,
여기서 뽑은 퀴즈는 **전부 틀린 문제**가 된다. 문법적으로 멀쩡해서 LLM 검증자도 못 잡는다.

→ 시리즈별 사전은 회당 20~30줄. **에피소드가 아니라 시리즈 단위로 1회 작성**하면 이후 전편에 재사용된다.

### S3 — 시각 접지 (독립 증거 채널)

**적응형 장면 검출.** 고정 0.35를 버리고 구간별 정규화 임계값을 쓴다.

```
윈도우(예: 10초)마다 평균 휘도·대비를 측정 → 임계값을 국소 스케일링
어두운 구간은 임계를 낮추고, 밝고 대비 높은 구간은 높인다
```

검증 기준은 이미 있다: **4:44–6:40 구간에서 39컷에 근접해야 한다.** 2컷이 나오면 실패다.

act별 대표 키프레임을 뽑아 비전 모델로 캡션한다. 이게 **§2에서 말한 독립 채널**이다 —
전사본이 오염돼도 프레임은 오염되지 않는다.

### S4 — act 분할 + 개입지점 스코어링

§1.5에서 무음 기반이 죽었으므로, **내레이션 종료를 1순위 신호로 쓴다.**

실측된 내레이션 비트 (`~습니다/했어요/있어요/네요/걸까요` 종결):

```
0:20  뽀로로네 집에 아직 불이 켜져 있네요
0:42  요술 양탄자가 별이 가득한 밤하늘로 날아올랐습니다
```

**분포가 좋다.** 무음 공백(16개, 3분 사막 2개)과 달리 12분에 고르게 8개.
게다가 **의미가 있다** — 내레이션 종료는 장면 전환이 아니라 **이야기의 장(章) 전환**이다.
아이의 몰입은 화면이 바뀔 때가 아니라 **한 사건이 끝날 때** 자연스럽게 풀린다.

도출된 act 구조:

| act | 구간 | 내용 | 활동 후보 |
|---|---|---|---|
| 1 | 0:11–0:55 | 알라딘 동화 (도입) | — (너무 이름) |
| 2 | 0:55–3:10 | 크롱의 꿈, 이불이 움직임 | 색깔 · 개수세기 |
| 3 | 3:10–4:00 | 뽀로로가 발견, 대화 | 의성어·의태어 |
| 4 | 4:00–5:30 | 비행 → 눈보라 → 이불 찢어짐 | 문장 배열(사건 순서) |
| 5 | 5:30–6:40 | 길을 잃음, 실을 발견 | 연관성 카드 |

| 7 | 8:30–9:25 | 집으로 귀환 | — |

**하드 금지 규칙** (스코어와 무관하게 무조건 차단):

1. 내레이션 문장 **도중**에 개입 금지
2. 다음 발화 시작 **2초 이내** 개입 금지
3. **11:05 이후 금지** — 엔딩 주제가 (실측 경계: 11:05.2 공백 후 11:06 주제가 시작)
4. 활동 간 **최소 150초** 간격
5. 12분 에피소드당 **최대 3~4개**
6. `quarantine` 스팬과 겹치는 지점 금지 — 타임스탬프 자체를 못 믿는다 (§1.1)

> 규칙 5가 이 설계에서 제일 지키기 어려운 부분이다. act가 9개고 활동 후보는 그보다 많다.
> **"넣을 수 있다"와 "넣어야 한다"는 다르다.** 12분 영상에 활동 8개를 꽂으면
> 그건 교육 앱이 아니라 광고 중간삽입이다. 아이는 두 번째에서 이탈한다.

### S5 — 생성 ↔ 검증 (2 에이전트)

act 단위로 실행. **각 에이전트는 해당 act의 증거 번들만 본다** (전체 영상 아님 — 문맥 오염 방지).

**증거 번들**

```json
{
  "act_id": 6,
  "span": [400, 510],
  "transcript": [
    {"t": [446, 449], "text": "혹시 바늘이랑 실 좀 빌려줄 수 있어?", "conf": "high"},
    {"t": [450, 452], "text": "당연하지!", "conf": "high"},
    {"t": [450, 455], "text": "너희도 소중한 내 실을 찾아줬잖아", "conf": "medium"}
  ],
  "frames": [
    {"t": 460, "id": "f460", "caption": "곰인형이 파란 이불을 바느질하고 있다"}
  ],
  "banned_spans": [[363, 394]]
}
```

- **에이전트 1 (생성)** — 증거만으로 활동을 제안. 스토리닷 카탈로그에 매핑
  (언어: 의성어·의태어 / 그리기 / 문장배열 / 연관성카드 / 색깔 · 수학: 개수세기 / 순서·부등호 / 퍼즐 · 그림감상문).
  모든 항목에 `source_span` + `quote` + `frame_id` **필수**.
- **에이전트 2 (검증)** — **같은 증거, 에이전트 1의 추론 과정은 미공개.**
  독립적으로 판정: 이 사실이 증거에 실제로 있는가? 답이 유일한가? 3세/5세에 적합한가?

에이전트 2가 에이전트 1의 근거를 못 보는 게 핵심이다. 근거를 보여주면 **검증이 아니라 추인**이 된다.

### S6 — 결정적 게이트 (LLM 판단 아님)

LLM 두 개가 합의해도 **이 관문을 통과해야 카드가 생성된다.**

```python
assert transcript_canonical[start:end] == card.quote      # 원문 일치
assert seg_confidence(start, end) in ("high", "medium")   # 오염 스팬 아님
assert not overlaps(card.span, quarantine_spans)          # 격리 구간 아님
assert card.frame_id in act.frames                        # 프레임 실재
# 불일치 → 카드 거부. 재시도 아님, 폐기.
```

**불변식은 이 하나뿐이다.** 소스가 늘어도, 활동 종류가 늘어도 이 검사는 늘지 않는다.
LLM 검증은 품질을 올리고, 이 대조는 **최악을 막는다.** 역할이 다르다.

### 런타임

파이프라인은 **전부 오프라인**. 재생 중에는 LLM 호출이 0회다.
플레이어는 `activity_plan.json`의 타임라인만 확인하고, 개입 지점에서 부드럽게 제안한다
(`모르겠어요` 건너뛰기 · 별사탕 보상 · 검증된 스팬에서만 단어장 자동 등록).

단어장이 검증된 스팬에서만 채워지는 게 중요하다. 안 그러면 아이가 **"크랑"을 단어로 배운다.**

## 5. 미해결 / 결정 필요

1. **오프라인 사전계산 vs 런타임 처리** — 이 설계는 편당 사전계산 전제다.
   심사·서비스에서 **임의 업로드 영상**을 즉석 처리해야 한다면 3중 ASR은 지연이 너무 크다
   (대안: small 단독 + 사전 + 시각 검증으로 축소).
2. **대상 연령** — 기획서에 3세/5세가 분리돼 있는데 act당 활동 난이도가 갈린다.
   한 편에 두 난이도를 다 넣을지, 프로필로 분기할지.
3. **시리즈 사전 초기 구축** — 신규 시리즈 첫 편은 사전이 없다.
   첫 편을 수동 교정해 사전을 만드는 부트스트랩 비용이 있다.
4. **적응형 장면 검출 미구현** — §3(S3)의 정규화 방식은 설계만 있고 아직 코드가 없다.
   검증 기준(4:44–6:40에서 39컷 근접)은 정의됨.
5. **`small` 우위가 이 영상 한정인지 미확인** — §1.3은 1편 기준 관측이다.
   다른 화·다른 시리즈에서도 성립하는지 확인 전. 합의 설계 자체는 이 결과와 무관하게 유효하지만,
   **패스 구성(turbo+small+VAD)이 최적인지는 근거가 1편뿐**이다.

# 부록 B — 구현 후 정정 (5편 교차 실행)

계획서 본문은 뽀로로 1편만 보고 쓴 것이다. 5편(뽀로로·티니핑·타요·브레드·아기상어)을
실제로 돌리자 **본문의 판단 여섯 개가 뒤집혔다.** 지운 게 아니라 무엇이 왜 틀렸는지 남긴다.

| # | 본문의 판단 | 실행 결과 | 정정 |
| --- | --- | --- | --- |
| 1 | 3중 합의 투표 | 앵커(VAD)가 재현율이 낮아 대부분 구간을 안 다룬다 | **침묵을 반박으로 치지 않는다.** 앵커가 겹칠 때만 판정, 아니면 판단 보류 |
| 2 | 사전이 손대면 `high` | "크롱! 크롱!" 옹알이가 최고 신뢰도가 됐다 (high 70건 중 60건이 이름 반복) | `high` = 사전 검증 **+ 내용성**. 이름 교정은 그 이름만 검증한다 |
| 3 | 이름 변이 자동 확정 | 최빈형이 `크랑`(오답)이라 정답 `크롱`을 덮어썼다 | **군집만 자동, 대표형은 사람이 확정.** 미확정이면 치환하지 않는다 |
| 4 | act 전체를 증거로 | 7:35 개입에 4:37 대사가 근거로 붙었다 | 개입 직전 **100초 회상창**만 |
| 5 | 발화 여유 부족 → 기각 | 대사 촘촘한 작품에서 후보가 전멸 (아기상어 4건 중 3건 기각) | 기각이 아니라 **앞쪽 공백으로 스냅** |
| 6 | 오디오만으로 타이밍 결정 | 9개 지점 중 3개가 동작 한복판 (바느질 클로즈업·점프·기차 주행) | **시각 정착 게이트 추가.** 화면이 잠잠한 순간이 없으면 그 지점을 버린다 |

## 침묵 ≠ 반박 (가장 큰 정정)

본문은 "앵커가 동의해야 medium"으로 썼다. 그런데 VAD 앵커는 환각이 0%인 대신 실제
대사의 약 30%를 통째로 버린다. 앵커가 말이 없는 것을 반박으로 취급하니 이렇게 됐다.

```
티니핑 167 세그먼트 중 medium 3개    → 개입지점 0개
브레드 237 세그먼트 중 ...            → 개입지점 0개
```

겹칠 때만 판정하고 안 겹치면 보류하도록 고친 뒤:

```
티니핑  medium 3 → 154    개입지점 0 → 3 (시각 게이트 후 2)
타요    medium 50 → 84    개입지점 1 → 3
뽀로로  medium 34 → 67    개입지점 2 → 2
```

**단일 에피소드 검증이 가린 결함이다.** 뽀로로만 봤을 때는 앵커 커버리지가 우연히 충분했다.

## 게이트가 실제로 잡은 것

생성 단계에서 개수 세기 문제를 만들며 `"친구들이 모여 있어요"` 라는 **존재하지 않는 인용**을
붙였다. 결정적 대조가 폐기했다.

```
[폐기] 개수 세기: 인용 불일치: '친구들이 모여 있어요' ∉ '뽀로로와 크롱은 정말 꿈을 꾼 걸까요?'
```

연출한 사례가 아니다. 시각 증거가 생성자에게 가지 않아서 없는 대사를 지어낸 것이고,
그게 이 설계가 존재하는 이유 그대로였다.

**그러나 같은 검사가 놓친 것도 있다.** 의성어 문제("꿰맬 때 어떤 소리? → 쓱쓱")는 인용
`꿰매기 시작했어요` 가 실재해서 통과했지만 **정답 "쓱쓱"은 증거 어디에도 없다.**
게이트가 인용은 보고 정답은 안 봤다. → `grounding.py` 로 분리 대응.

## 남은 한계

- **움직임 수치가 컷과 동작을 구분 못 한다.** 컷은 픽셀 차이가 튀지만 멈추기 좋은 지점이다.
  타요 4:36이 37.0으로 찍혔는데 육안으로는 정적인 와이드샷이었다.
- **샷 크기를 못 본다.** 뽀로로 7:35 바느질 클로즈업은 바늘이 느려서 5.8(정지 판정)을
  받았다. 수치는 조용한데 서사적으로는 동작 한복판이다.
- **브레드는 개입지점 0개.** 대사가 쉬지 않는 작품이다. 억지로 넣지 않고 0을 반환한다.
- **티니핑 경계에 의미가 없다.** 내레이터가 없어 무음 공백으로 잘랐더니 라벨이
  `(무음 전환 바범이 훌륭다!)` 가 됐다. 무엇이 끝났는지 알 수 없다.
