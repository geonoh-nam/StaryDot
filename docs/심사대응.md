# 스토리닷 — 평가 기준 대응

> 각 항목마다 **주장 → 근거 → 확인 방법**을 붙였다. 확인 방법은 심사위원이 직접 돌릴 수 있는
> 명령이거나 레포 안의 파일 경로다. 근거 없는 주장은 넣지 않았고, 약한 항목은 약하다고 적었다.

## 1. 혁신성 및 AI 기술 활용 (20)

### 1-1. 아이디어의 독창성 및 우수성 (10)

**기존 방식과 무엇이 다른가.**

영상으로 교육 콘텐츠를 만드는 통상적 접근은 *"영상 요약을 LLM에 넣고 퀴즈를 뽑는다"* 이다.
이 방식은 두 가지를 아예 문제로 인식하지 않는다.

| | 통상적 접근 | 스토리닷 |
| --- | --- | --- |
| **언제 끼어드는가** | 고정 간격 또는 챕터 단위 | 이야기 단락 + 화면 정지 + 발화 여유를 **동시에** 만족하는 지점만 |
| **할루시네이션** | 프롬프트로 "지어내지 마세요" | 결정적 문자열 대조. LLM 판단이 아니다 |
| **근거 추적** | 없음 | 모든 활동이 `타임스탬프 + 원문 인용 + 프레임 ID` 보유 |

**독창성의 핵심 — "교차검증"의 통념을 실측으로 반박했다.**

*"두 에이전트가 교차검증하면 할루시네이션이 없어진다"* 는 널리 쓰이는 전제다.
이 프로젝트는 그것이 **원리적으로 불충분함**을 데이터로 보였다.

```
정답    "이제 날 수 있겠어?"   (이불을 다 꿰맸으니 다시 날 수 있는가)
────────────────────────────────────────────────────────────
small        → 날씨 있겠어      ✗
turbo        → 날씨 있겠어      ✗      세 패스가 독립적으로 틀렸는데
turbo + VAD  → 날씨 있겠어      ✗      셋 다 같은 오답으로 수렴했다
```

세 모델이 같은 음향적 모호성과 같은 언어모델 편향을 공유하기 때문이다. 다수결로 재면
이 구간은 **`high` 신뢰도를 받고** 그대로 퀴즈가 된다. 프롬프트를 아무리 다르게 짜도 막을 수 없다.

> **결론: 교차검증의 독립성은 프롬프트가 아니라 증거 채널에서 나와야 한다.**
> 그래서 (a) 검증 층을 ASR·활동 두 개로 나누고 (b) 최종 관문을 LLM이 아닌 결정적 대조로 닫았다.

**확인 방법** — `docs/PIPELINE_PLAN.md` §1.3 / 부록 B. 원본 전사본 5종이 `work/*.json` 에 커밋돼 있다.

### 1-2. AI 기술 적용의 적절성 및 우수성 (10)

**적재적소에 다른 기술을 썼다. 전부 LLM으로 밀지 않았다.**

| 문제 | 선택한 기술 | 왜 이것인가 |
| --- | --- | --- |
| 한국어 STT | `whisper.cpp` 로컬 다중 패스 | API 키 0개, 종량 과금 0. 쿼터 제약 없이 반복 실행 |
| BGM 하 환각 | Silero VAD 게이팅 | 환각 23.5% → **0.0%** (실측) |
| VAD의 재현율 손실 | 재현율 패스와 정밀도 패스를 **역할 분리** | 단일 최적 설정이 존재하지 않음을 측정으로 확인 |
| 등장인물 오인식 | **한글 자모 분해 + 편집거리 클러스터링** | 형태소 분석기 없이 `크롱 ← 크랑/크라/클랑/크롬` 자동 수렴 |
| 개입 타이밍 | 프레임 차분 시계열의 **컷/지속동작 분리** | 컷은 멈추기 좋은 자리, 지속동작은 나쁜 자리 — 구분해야 함 |
| 색 근거 | 결정적 색 양자화 (k-means 아님) | 어차피 11개 한국어 색이름으로 접히므로 군집 정밀도가 무의미 |
| 활동 생성·검증 | **`claude` CLI 별도 프로세스 2개** | 같은 문맥을 공유하면 검증이 아니라 추인이 된다 |

**모델 선택을 실측으로 뒤집은 사례.**

```
large-v3-turbo (1.5GB)  환각 23.5%
small          (465MB)  환각  9.1%      ← 3배 작은 모델이 2.6배 정확했다
```

6:03–6:33 구간에서 turbo는 "크롱" 73회를 반복하며 30초를 통째로 날렸고, small은
`"예쁜 실이네" / "이걸로 이불을 꿰매주자" / "동굴 깊숙이 들어갔습니다"` 를 복원했다.
**이 구간은 에피소드 교훈의 도입부다.** turbo만 썼으면 act 하나가 증발한다.

**확인 방법** — `python3 -c "import storydot, motion, visual, beats, grounding"` 후 각 모듈 자체검사.

## 2. 목표 달성도 및 구현능력 (20)

### 2-1. 문제의 핵심 목표 달성도 (10)

스스로 정의한 목표는 둘이다. 각각 검증 가능한 기준을 세워 두고 측정했다.

**목표 A — 아이가 방해받았다고 느끼지 않을 것.**

기준: 개입 지점의 화면이 (a) 동작 한복판이 아니고 (b) 익스트림 클로즈업이 아니며
(c) 다음 발화까지 페이드아웃 여유가 3초 이상일 것.

```
개선 전   9개 지점 육안 검증 → 5개 적절 · 3개 동작 한복판 · 1개 애매
개선 후   7개 지점 육안 검증 → 7개 전부 적절
```

가장 나빴던 뽀로로 7:35(바늘이 이불을 꿰매는 익스트림 클로즈업)가
**곰인형·크롱·뽀로로가 다 보이는 와이드샷**으로 교정됐다.

**목표 B — 근거 없는 활동을 내보내지 않을 것.**

기준: 모든 활동이 원문 인용 대조와 정답 근거 검사를 통과할 것. 실제로 두 종류를 차단했다.

```
[폐기] 개수 세기  인용 위조 — '친구들이 모여 있어요' 는 전사본에 없다
[폐기] 의성어     정답 조작 — 인용은 진짜인데 정답 '쓱쓱' 이 증거 어디에도 없다
```

두 번째가 중요하다. 인용만 검사하는 게이트는 이걸 **통과시킨다.** 정답 근거 검사를
따로 만든 이유이며, 아이에게 틀린 것을 가르치지 않는 마지막 방어선이다.

**확인 방법** — `verify/` 의 프레임 7장, `python3 grounding.py`, `python3 activities.py`.

### 2-2. 제안 솔루션의 구현 완성도 (10)

**동작하는 파이프라인이다. 슬라이드가 아니다.**

```bash
./setup.sh                                  # 의존성 + 모델 자동 준비
python3 storydot.py ~/Downloads/타요1화.mp4   # → 개입지점 + 증거번들
python3 generate.py work/타요1화_plan.json     # → 활동 자동 생성·검증
```

서로 다른 5개 작품에서 end-to-end 동작을 확인했다.

| 작품 | 길이 | act 탐지 방식 | 개입지점 | 생성 활동 |
| --- | --- | --- | --- | --- |
| 타요 | 10:09 | 내레이션 | 3 | 8 채택 / 3 폐기 |
| 뽀로로 | 12:42 | 내레이션 | 2 | (생성 중) |
| 티니핑 | 12:58 | **다중신호** (내레이터 없음) | 1 | (생성 중) |
| 아기상어 | 11:28 | 내레이션 | 1 | (생성 중) |
| 브레드 | 10:54 | 내레이션 | **0** | — |

**브레드의 0이 결함이 아니라 설계다.** 대사가 쉬지 않아 페이드아웃 3초를 확보할 수 없다.
억지로 넣는 대신 0을 반환하고 기각 사유를 남긴다. 근거가 얇으면 만들지 않는 것이 정상 동작이다.

- 모듈 6개 전부 `python3 <파일>.py` 자체검사 통과 (실제 영상으로 검증)
- 외부 파이썬 패키지 **0개**. 표준 라이브러리 + ffmpeg + whisper-cli
- 전사본 15종을 회귀 픽스처로 커밋 — 환각율·경계 검출 수치가 재현된다

## 3. 확장성 및 지속 가능성 (25)

### 3-1. 결과의 확장성 및 지속 가능성 (15)

**지속 가능성 — 외부 API 의존이 0이다.**

이것이 이 설계의 가장 큰 구조적 강점이다.

| 단계 | 비용 | 벤더 종속 |
| --- | --- | --- |
| 인제스트·프레임 | ffmpeg, 로컬 | 없음 (OSS) |
| STT ×2~3 패스 | whisper.cpp, 로컬 | 없음 (OSS, 모델 로컬 보관) |
| 이름 수렴·경계 탐색·색 분석 | 순수 파이썬 | 없음 |
| 활동 생성·검증 | LLM, **편당 1회 (오프라인)** | 교체 가능 |
| **재생 중** | **0회** | **없음** |

프로젝트가 끝난 뒤에도 계속 쓸 수 있는지가 평가 항목인데, **끊길 지점이 재생 경로에 없다.**
LLM 벤더가 가격을 올리거나 모델을 폐기해도 이미 생성된 `activity_plan.json` 은 그대로 동작한다.
생성 단계도 CLI 호출 한 줄이라 다른 모델로 교체 가능하다.

**확장 축 넷 — 각각 무엇을 바꿔야 하는지 명시한다.**

| 축 | 바꿔야 하는 것 | 안 바꿔도 되는 것 |
| --- | --- | --- |
| **회차 확장** | 없음 | 시리즈 사전을 1회 확정하면 전 회차 재사용 |
| **작품 확장** | `series/<작품>.json` 1개 (약 20줄) | 코어 전부 |
| **언어 확장** | `transcribe(lang=…)` 인자, 내레이션 종결 패턴 | 파이프라인 구조, 게이트 불변식 |
| **도메인 확장** | 활동 유형 목록 (SKILL.md) | **인용 대조 불변식은 도메인 무관** |

도메인 확장이 특히 넓다. 아동 애니메이션 → **초·중등 인강, 사내 교육 영상, 안전 교육,
박물관 도슨트**. 공통 구조가 같기 때문이다 — *긴 영상이 있고, 중간에 이해를 확인해야 하고,
확인 문항이 영상 내용에 근거해야 한다.*

**한계비용이 사실상 0이다.** M2 Pro 노트북 기준 12분 1편에 약 3분. GPU 서버도, 종량 과금도 없다.
1,000편을 처리해도 추가로 드는 것은 전기값과 시간뿐이다.

### 3-2. 결과의 파급 효과 (10)

**기술적 파급 — "근거 없는 생성 차단" 패턴은 아동 교육 밖에서 더 가치가 크다.**

이 프로젝트의 핵심 자산은 퀴즈가 아니라 **불변식 하나**다.

```
생성물의 모든 주장은 원본 스팬을 인용해야 하고,
그 인용은 원문과 문자열 단위로 일치해야 하며,
정답 역시 그 증거에서 도출되어야 한다.
불일치는 재시도가 아니라 폐기다.
```

이 패턴은 **틀리면 안 되는 도메인** 전반에 그대로 이식된다 — 의료 상담 요약, 법률 문서 검토,
금융 리포트, 규제 대응 문서. 어느 쪽이든 "그럴듯한 문장"과 "근거 있는 문장"을 기계적으로
가르는 장치가 필요하고, LLM 판단으로는 그 경계를 못 긋는다는 것을 이 프로젝트가 실측으로 보였다.

**산업적 파급 — 영상 자산의 학습 자산화.**

국내 아동 애니메이션만 수천 편, 교육 영상까지 넓히면 수십만 편이 이미 존재한다.
현재는 사람이 보고 교안을 만들어야 해서 대부분 방치돼 있다. 이 파이프라인은
그 병목을 **편당 3분·한계비용 0** 으로 낮춘다.

부수 효과로, 검증에 실패한 구간이 **콘텐츠 품질 지표**가 된다. 예를 들어 브레드가
개입지점 0개를 낸 것은 "대사 밀도가 지나치게 높아 아이가 쉴 틈이 없는 편"이라는
제작 피드백이기도 하다.

## 4. ESG 연계 및 기대효과 (25)

### 4-1. 사회문제 해결 및 ESG 기여도 (15)

**S — 유아 미디어 과의존을 "수동 시청"에서 "능동 참여"로 바꾼다.**

문제의 실체는 스크린타임의 **길이**가 아니라 **성격**이다. 같은 20분이라도 일방적으로
받아보는 20분과 중간에 생각하고 대답하는 20분은 다르다. 이 파이프라인은 12분 영상에
평균 2~3회, 아이의 몰입을 깨지 않는 지점에만 개입한다. **개입 횟수 상한을 설계에 못 박았다** —
많이 넣을수록 좋은 구조가 아니다.

**S — 아동 안전이 곧 할루시네이션 차단이다.**

성인 대상 서비스에서 LLM이 틀린 답을 내면 사용자가 걸러낸다. **유아는 못 거른다.**
"이불을 꿰맬 때 쓱쓱 소리가 난다"를 사실로 받아들인다. 그래서 이 프로젝트는 정확도를
품질 지표가 아니라 **안전 요건**으로 취급했고, 결정적 게이트를 최후단에 놓았다.

같은 이유로 단어장도 검증된 스팬에서만 채운다. 안 그러면 아이가 **"크랑"을 단어로 배운다.**

**S — 사교육 격차 완화.**

개인화 학습 활동은 현재 고비용 서비스다. 이 파이프라인은 한계비용이 0에 가까워
무료·저비용 배포가 구조적으로 가능하다. 특히 로컬 실행이라 **인터넷 연결이 불안정한 환경**
(도서·산간, 저소득 가구, 해외 한글학교)에서도 동작한다.

**E — 로컬 추론으로 클라우드 GPU 호출을 없앴다.**

STT를 클라우드 API로 돌리면 영상 1편에 3회의 원격 추론이 발생한다. 이 파이프라인은
전부 온디바이스다. 재생 시점에는 추론이 **0회**다 — 사전 계산된 JSON만 읽는다.
1,000편 규모에서 클라우드 대비 절감되는 것은 API 호출 3,000회와 그에 따른 데이터 전송이다.

**G — 모든 활동에 감사 추적(audit trail)이 남는다.**

아동 대상 AI 서비스의 설명 책임이 규제 논의 대상이 되고 있다. 이 파이프라인은
**모든 활동 카드가 `타임스탬프 + 원문 인용 + 프레임 ID + 신뢰도 등급`을 보유**한다.
"이 문제가 왜 나왔는가"에 대해 영상의 몇 분 몇 초를 짚어 답할 수 있다.
폐기된 카드와 그 사유도 함께 저장된다 — 무엇을 걸러냈는지까지 남는다.

부모 리포트가 "AI가 그렇게 판단했습니다"가 아니라 **"7분 31초 장면의 이 대사에 근거합니다"**
가 되는 것이 실질적 차이다.

### 4-2. 실현 가능성 및 기대효과 (10)

**실현 가능성 — 이미 실현돼 있다.**

가설이 아니라 5개 상용 애니메이션에서 end-to-end로 동작하는 코드다.

| 항목 | 값 |
| --- | --- |
| 처리 시간 | 12분 1편에 약 3분 (M2 Pro 노트북) |
| 필요 하드웨어 | 일반 노트북. GPU 서버 불필요 |
| API 키 | **0개** |
| 종량 과금 | **0원** |
| 외부 파이썬 패키지 | **0개** |
| 재현 절차 | `./setup.sh` 한 번 |

도입 장벽이 낮은 것이 핵심이다. 계정 발급도, 인프라 구축도, 예산 승인도 필요 없다.

**기대효과 — 정량**

- 교안 제작: 사람이 1편당 수 시간 → **3분**, 한계비용 0
- 재생 시 추론 비용: **0** (사전 계산)
- 시리즈 온보딩: 사전 확정 1회(약 20줄)로 전 회차 적용

**기대효과 — 정성**

- 아이: 수동 시청 → 능동 참여. 방금 본 장면에 근거한 질문이라 맥락이 끊기지 않는다
- 부모: 무엇을 배웠는지 **근거와 함께** 확인
- 콘텐츠 제작사: 기존 영상 자산의 재활용 경로 확보

**정직하게 적는 한계** — 교육 효과 자체는 아직 측정하지 않았다. 이 프로젝트가 검증한 것은
*"적절한 타이밍에 근거 있는 활동을 자동으로 만들 수 있는가"* 까지이며, *"그 활동이 실제로
학습에 도움이 되는가"* 는 아동 대상 사용자 연구가 필요하다. 그것을 다음 단계로 둔다.

## 5. 발표 전달력 (10)

### 5-1. 발표 자료의 논리성 및 충실성 (5)

문서 구조를 **배경 → 과정 → 결과** 로 분리했다.

| 문서 | 역할 |
| --- | --- |
| `README.md` | 무엇을 만들었고 왜 이 설계인지. 5분 안에 파악 가능 |
| `docs/PIPELINE_PLAN.md` | 설계 근거와 실측 데이터. 재현 명령 포함 |
| `docs/PIPELINE_PLAN.md` 부록 B | **뒤집힌 판단 6개.** 실패 경로를 지우지 않았다 |
| `docs/심사대응.md` | 이 문서. 평가 항목 ↔ 근거 매핑 |
| 각 모듈 상단 주석 | 그 모듈이 존재하는 이유와 임계값 근거 |

**충실성의 근거는 "틀린 것을 남겨 뒀다"는 점이다.** 엔딩 경계 검출은 네 번 만에 맞았고,
그 세 번의 실패와 원인을 전부 코드 주석과 문서에 남겼다.

```
① 600초 이후 첫 1.5초 공백  → 10:06   짧은 숨을 오인
② 후반 1/3 최대 공백        →  9:33   장면전환이 10초로 최대였다
③ 마지막 내레이션 + 3초 공백 →  9:17   정규식이 물음표를 못 받았다
④ 종결부호 [.?!] 로 수정     → 11:05  ✓ 실측 무음 공백과 일치
```

### 5-2. 발표 내용의 전달력 및 설득력 (5)

**시연 시나리오 — 3분.**

1. **문제 (30초)** — 뽀로로 6:03–6:33 구간의 turbo 전사본을 그대로 보여준다.
   `"크롱 크롱 크롱 …"` ×73. *"이 30초로 퀴즈를 만들면 어떻게 되겠습니까."*
2. **통념 반박 (45초)** — 세 모델이 `날씨 있겠어` 로 **수렴**한 표.
   *"교차검증으로는 못 막습니다. 셋 다 같은 답을 냈으니까요."*
3. **동작 (60초)** — 타요 1편을 실제로 돌린다. 개입지점 3개와
   `주차장에 버스가 몇 대 서 있나요? → 4` 가 나오는 화면.
4. **차단 (30초)** — 게이트가 잡아낸 두 카드. *"이건 저희가 지어낸 게 아니라
   생성 에이전트가 실제로 만든 것이고, 시스템이 폐기했습니다."*
5. **확장 (15초)** — API 키 0개, 재생 시 추론 0회, 도메인 무관 불변식.

**설득력의 축은 "우리도 틀렸고, 그걸 어떻게 잡았는가" 다.** 잘된 결과만 보여주는 발표보다
실패를 측정해 고친 과정을 보여주는 쪽이 기술적 신뢰를 만든다.
