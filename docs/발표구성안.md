# 스토리닷 — 최종 발표 구성안

> SK텔레콤 FLY AI Challenger 8기 최종 발표. 5팀(MUSIC SENSE)·2팀(REALY.AI) 자료의
> 공통 뼈대에 스토리닷을 매핑했다. 각 장에 **무엇을 말할지 · 어느 파일이 근거인지 ·
> 지금 있는지 없는지**를 붙였다. 없는 것은 `[보강]` 으로 표시했다.

두 팀의 공통 골격:
`① 사회문제 정의 → ② 자체 설문·인터뷰로 수요 입증 → ③ 아키텍처와 정량 성능 → ④ 실사용 검증 → ⑤ 확장성·사회적 가치`

스토리닷은 ③이 두 팀보다 두껍고, ②와 ④가 비어 있다. 이 구성안은 **③의 밀도를
발표의 무기로 쓰되, ②·④를 최소한으로라도 채우는 것**을 전제로 짰다.

---

## 기술 설명 원칙

본문은 **일상어로만** 간다. ASR·VAD·앵커·정본·게이트 같은 말은 한 장도 쓰지 않는다.
기술 심사위원을 위한 원본 구조도와 용어 대조표는 **부록 I·J**에 그대로 남겨 두고,
질문이 들어오면 그 두 장을 편다. 청중이 섞여 있을 때 가장 안전한 배치다.

핵심 비유 하나로 관통한다 — **영상 한 편을 네 사람이 나눠서 본다: 귀 · 눈 · 출제 · 검사.**

---

## 발표의 한 문장

> **"아이에게 틀린 것을 가르치지 않는 방법은, LLM에게 지어내지 말라고 부탁하는 게 아니라
> 지어낼 표면 자체를 없애는 것이다."**

5팀의 반전 오프닝("청각장애인 = 못 듣는 사람? NO!")에 대응하는 스토리닷의 반전은
**"교차검증하면 환각이 없어진다"는 통념을 실측으로 뒤집은 것**이다. 이게 발표의 축이다.

## PART 2 — 왜 지금까지 안 됐는가 (2장)

**6p 통상적 접근과 무엇이 다른가**

| | 통상적 접근 | 스토리닷 |
|---|---|---|
| 언제 끼어드는가 | 고정 간격 / 챕터 단위 | 이야기 단락 + 화면 정지 + 발화 여유를 **동시에** 만족하는 지점만 |
| 지어낸 답 | 프롬프트로 "지어내지 마세요" | 원문과 글자 대조. AI 판단이 아니다 |
| 근거 추적 | 없음 | 모든 문제가 `몇 분 몇 초 + 그때 나온 대사 + 그 화면` 보유 |

**7p 유아 안전 = 지어낸 답 차단** ★ 이 프로젝트의 윤리적 좌표
- 성인은 AI가 틀린 답을 내면 **거른다.** 유아는 **못 거른다**
- "이불을 꿰맬 때 쓱쓱 소리가 난다"를 사실로 받아들인다
- 그래서 정확도는 품질 지표가 아니라 **안전 요건**이다
- 같은 이유로 단어장도 검증된 문장에서만 채운다 — 안 그러면 아이가 **"크랑"을 단어로 배운다**

## PART 3 — "그럼 이렇게 하면 되지 않나요?" (3장) ★ 발표의 핵심

> 5팀의 INTRO 반전, 2팀의 딥페이크 사례 자리.
> **"저희도 순진하게 시작했고, 실측이 우리를 뒤집었다"** 가 서사의 축이다.
> 세 장 모두 **질문 → 해봤다 → 이렇게 실패했다 → 그래서 이렇게 고쳤다** 순서로 통일한다.

**9p 질문 ① "AI 두 개를 붙여서 서로 검사시키면 되지 않나요?"**
```
실제 대사      "이제 날 수 있겠어?"
──────────────────────────────────────────────
1번 방식   →   날씨 있겠어    ✗
2번 방식   →   날씨 있겠어    ✗   셋이 따로따로 틀렸는데
3번 방식   →   날씨 있겠어    ✗   답이 똑같이 나왔다
```
- 셋이 같은 답을 내니, 다수결로는 오히려 **가장 믿을 만한 문장**이 된다
- 셋 다 같은 소리를 듣고 같은 언어 습관을 배웠기 때문 — 서로 검사시켜도 같은 곳에서 같이 넘어진다
- **검사는 같은 종류로 여러 번이 아니라 아예 다른 종류로 해야 한다** → 그래서 '귀'와 '눈'을 따로 쓴다

**10p 질문 ② "더 크고 좋은 AI를 쓰면 되지 않나요?"**
```
큰 모델 (1.5GB)   지어낸 말 23.5%    영상의 4분의 1
작은 모델 (465MB) 지어낸 말  9.1%    3배 작은 쪽이 2.6배 정확했다
```
- 6:03–6:33에서 큰 모델은 "크롱"을 **73번** 반복하며 30초를 통째로 날렸다
- 하필 그 30초가 **그 회차의 교훈이 시작되는 대목**이다
- 등장인물 이름을 미리 알려줘도 결과가 소수점까지 같았다 → 작품별 이름 사전이 따로 필요한 이유

**11p 질문 ③ "배경음악을 걸러내면 되지 않나요?"**
```
목소리 구간만 골라 듣기 → 지어낸 말 23.5% → 0%
                          하지만 문장 160개 → 70개. 진짜 대사의 30%도 사라졌다
```
- 이 두 번째 받아쓰기를 '검사관'으로 쓰면서, **검사관이 안 적은 것까지 "틀렸다"로 처리**하고 있었다
- **말이 없는 것은 반대한다는 뜻이 아니다** — 검사관이 다룬 부분만 판정하고 안 다룬 부분은 판단 보류
- 티니핑 쓸 수 있는 문장 **3 → 154 (51배)**, 문제 낼 지점 0 → 3곳
- 뽀로로 한 편만 봤을 때는 2배로 보여서 못 찾았다

## PART 4 — 어떻게 만들었나 (7장)

> 원칙 하나로 관통한다: **AI에게 "지어내지 마세요"라고 부탁하지 않았다. 지어낼 자리를 없앴다.**
> 기술 용어는 전부 부록으로 내리고, 본문은 일상어로만 간다.

**12p 전체 그림 — 영상 한 편을 네 사람이 나눠서 본다** ★
```
① 귀   말을 받아 적는다      같은 영상을 두 가지 방식으로 듣고, 문장마다 얼마나 믿을 수 있는지 표시
② 눈   화면만 따로 본다      말은 안 듣는다. 멈춰도 되는 순간 / 무엇이 몇 개, 무슨 색인지만
③ 출제 AI가 문제를 만든다    단, 정답은 못 쓴다. 앞에서 세어 둔 값이 그대로 들어간다
④ 검사 기계가 마지막에 대조   문제에 쓴 대사가 대본에 정말 있는지. 판단이 아니라 대조
```
세 문장으로 요약: ① 서로 다른 감각으로 두 번 본다 ② 정답은 AI가 쓰지 않는다 ③ 마지막은 기계가 대조한다

**13p [귀] 받아 적은 문장마다 얼마나 믿을 수 있는지 표시한다**
| 표시 | 뜻 |
|---|---|
| 확실함 | 등장인물 이름이 확인됐고, 내용이 있는 문장 |
| 보통 | 두 번째 받아쓰기와 어긋나지 않음 (또는 그 부분을 안 다룸) |
| 의심 | 두 번째 받아쓰기가 실제로 다르게 들음 |
| 폐기 | 지어낸 말로 판정. 근거로 쓰지 않음 |
- **'확실함'을 줄인 것이 개선이었다** — 이름 하나만 맞으면 확실함을 줬더니 `[확실함] 크롱! 크롱!` 같은 옹알이가 최고 등급을 받았다. 뽀로로 214문장 중 확실함 70개의 약 60개가 이름 반복. 내용 조건을 걸어 70 → 10

**14p [눈] 화면이 조용하다고 멈춰도 되는 건 아니다** (프레임 2장)
- 타요 4:36 — 변화량이 커서 '한창 움직이는 중'으로 버렸다. 실제로는 장면이 탁 바뀐 정지 화면 → **좋은 자리를 버렸다**
- 뽀로로 7:35 — 변화량이 작아서 '조용하다'고 통과시켰다. 실제로는 바늘 끝만 확대된 화면 → **나쁜 자리를 통과시켰다**
- **두 실수가 정반대 방향이다.** 장면 전환과 캐릭터 움직임은 변화량이 둘 다 크게 나온다
- 결과: 사람이 프레임을 열어 판정한 적중률 **5/9(56%) → 7/7(100%)**

**15p [눈] 모든 만화에 같은 잣대를 대면 무너진다 — 세 번 겪었다**
| 무엇을 찾을 때 | 처음에 쓴 기준 | 무슨 일이 벌어졌나 | 어떻게 고쳤나 |
|---|---|---|---|
| 장면이 바뀌는 순간 | 화면이 35% 이상 바뀌면 전환 | 어두운 눈보라 장면에서 2번만 찾았다 (실제 39번) | 그 구간 안에서 상대적으로 |
| 확대된 화면인지 | 화면이 단순하면 확대 | 그림이 단순한 아기상어는 전 장면이 '확대' → 지점 1 → 0곳 | 그 작품의 평균과 비교 |
| 본편이 끝나는 지점 | 가장 긴 무음 구간 | 두 번 연속 엉뚱한 곳 (1분 전, 1분 32초 전) | 무음 길이가 아니라 '누가 말했는가' |

**16p [눈] 재료를 미리 창고에 쌓고, 보는 사람과 내는 사람을 나눴다**
- 예전엔 멈출 자리를 먼저 고르고 그 앞 100초만 뒤졌다 → 브레드는 멈출 자리가 0곳이라 재료를 한 번도 안 봤다. **전체의 15.7%만 조회**
- 화면 담당은 "무엇이 몇 개, 무슨 색"만 적는다. **문제는 안 만든다** — 자기가 본 것에 유리하게 낼 여지를 막았다
- **그리고 그 말을 컴퓨터가 반박한다** — 화면의 색은 미리 기계적으로 세어 둔다. "초록 인형"이라 적었는데 그 화면에 초록이 없으면 버린다
- **AI의 말을 다른 AI가 아니라 산수가 검사한다.** 사물 109건 중 9건(8.3%) 폐기

**17p [검사] 마지막 검사는 AI가 하지 않는다** ★
| # | 검사 | 방식 |
|---|---|---|
| 1 | 근거로 적은 번호가 실제로 있는가 | 글자 대조 |
| 2 | 문제에 쓴 대사가 대본에 글자 그대로 있는가 | 글자 대조 |
| 3 | 그 대사가 정말 그 장면의 것인가 | 글자 대조 |
| 4 | 정답이 그 근거에서 나오는가 | 일부 판단 |
| 5 | 정답으로 쓴 색이 그 화면에 실제로 있는가 | 픽셀 계산 |
- **걸리면 다시 만들지 않는다. 버린다**
- 채점하는 쪽을 문제 만드는 쪽 **밖에** 두었다 — 두 방식이 각자 8.3%와 3.8%를 주장했는데 자가 서로 달랐다
- 문제 만드는 AI와 검토하는 AI는 아예 따로 띄운다. 같은 대화 안에 두면 검증이 아니라 자기 확인이 된다

**18p [핵심] AI에게 정답 칸을 주지 않았다** ★ 가장 강한 설계 판단
```
개수 문제   정답 = 화면에서 미리 세어 둔 개수
크기 문제   정답 = 미리 재둔 큼 / 작음
색 문제     정답 = 미리 뽑아 둔 색
```
- AI가 하는 일은 **"이 재료로 이런 질문을 내자"를 고르는 것뿐** → 지어낼 칸이 아예 없다
- 동시에 회상 부담도 없앴다: `"버스가 몇 대였나요?"`(12분 전 기억) → `"이 그림에 버스가 몇 대 있나요?"`(눈앞에서 셈)
- 영상 중간이 아니라 끝난 뒤로 옮기면서 **대사 밟기 · 절정에서 끊기 · 확대 화면 오판 · 브레드 0곳**이 한꺼번에 사라졌다
- **그림 없는 문제는 만들기를 거부한다**

**21p 환각률 — 10.7% → 1.7% (고정 판정기 실측)** ★ 새 수치, 반드시 넣을 것
```
              카드    환각   환각률
v1 (자유 생성)  28      3    10.7%
v2 (재료 기반) 115      2     1.7%     ← 카드는 4배, 환각은 1/6
```
- 자체검사 10/10 통과. **판정기는 arm 밖에 고정돼 있다**
- 재현: `python3 judge.py`

**22p 게이트가 실제로 잡은 것 — 연출이 아니다** ★ 2팀의 위험 3요소 자리

[폐기] 개수 세기   인용 위조

[폐기] 의성어      정답 조작
       quote "꿰매기 시작했어요"  ← 원문에 실재. 인용 게이트는 통과한다
       answer "쓱쓱"             ← 증거 어디에도 없음. 정답 게이트가 잡았다

[폐기] 색깔 퀴즈   검증자가 프레임을 열어 반박

[폐기] 색깔 퀴즈   연령 수준 초과 (정답은 맞다)

## PART 6 — 데모와 검증 (4장)

**23p 앱 흐름** — `Package → Watch → Break → Mission → Bye`
- 브레이크는 **영상 사이**에만 붙는다. 몰입을 자르지 않는다
- 미션 카드는 **화면 밖 활동**으로 세션을 착지시킨다

**24p 세션 편성 — 보호자가 정한 예산 안에 영상과 활동이 전부 들어간다**
```
total(k) = Σ(영상 길이) + (k−1) × 40초 + 20초
                          브레이크        미션 카드
```
| 예산 | 편성 |
|---|---|
| 10분 | 6분 + 1분 + 미션 · 총 8분 26초 |
| 20분 | 10분 + **브레이크 2문항** + 6분 + 1분 + 미션 · 총 19분 15초 |
- **퀴즈도 화면을 보는 시간이다.** 그래서 예산에 포함했다
- 퀴즈 개수가 영상 개수에 종속되므로 고정 용량 배낭문제가 아니다

**25p 실제 산출물** — 실기기 시연 `[보강: 30초 시연 영상 녹화]`
```
✓ 색깔 퀴즈   이 그림에서 버스는 무슨 색인가요?      보라/분홍/파랑 → 파랑   근거 프레임 108s
✓ 개수 세기   이 그림에 빨간 차가 몇 대 있나요?       2/4/3 → 3              근거 프레임 240s
✗ 색깔 퀴즈   [폐기] 안전한 오답 색이 모자란다
```
- 5편 전편에서 마무리 활동 **21건 채택 / 4건 폐기**

**26p 사람이 전수 검증했다**
| 축 | 결과 |
|---|---|
| 개입 타이밍 7곳 | 프레임을 직접 열어 판정 → **7/7 적절** |
| 화면 근거 카드 8건 | **직접 세어 확인 → 오답 0건** |
| 누리과정 매핑 26건 | 4개 영역 고른 분포 · 창작형 27% 확보 |
- **생성자와 검증자의 말을 믿지 않고 프레임을 열었다**
- `[보강]` 여기에 **아동 3~5명 실사용 세션 관찰**이 붙으면 5팀 수준이 된다

## PART 7 — 확장성과 ESG (4장)

**27p 지속 가능성 — 끊길 지점이 재생 경로에 없다** ★ 3-1 대응
| 단계 | 비용 | 벤더 종속 |

| **재생 중** | **0회** | **없음** |
- LLM 벤더가 가격을 올리거나 모델을 폐기해도 **이미 생성된 JSON은 그대로 동작한다**

**28p 확장 4축 — 무엇을 바꿔야 하는지 명시한다**
| 축 | 바꿔야 하는 것 | 안 바꿔도 되는 것 |
|---|---|---|
| 회차 | 없음 | 시리즈 사전 1회 확정 → 전 회차 재사용 |
| 작품 | `series/<작품>.json` 1개 (약 20줄) | 코어 전부 |
| 언어 | `transcribe(lang=…)` · 내레이션 종결 패턴 | 파이프라인 구조, 게이트 불변식 |
| 도메인 | 활동 유형 목록 (SKILL.md) | **인용 대조 불변식은 도메인 무관** |
- 도메인 확장: 아동 애니 → **초·중등 인강 · 사내 교육 · 안전 교육 · 박물관 도슨트**
- 공통 구조가 같다: *긴 영상 · 중간 이해 확인 · 문항이 내용에 근거해야 함*

**29p 핵심 자산은 퀴즈가 아니라 불변식 하나다** ★ 3-2 파급효과
```
생성물의 모든 주장은 원본 스팬을 인용해야 하고,
그 인용은 원문과 문자 단위로 일치해야 하며,
정답 역시 그 증거에서 도출되어야 한다.
불일치는 재시도가 아니라 폐기다.
```
- **틀리면 안 되는 도메인** 전반에 이식된다 — 의료 상담 요약 · 법률 문서 검토 · 금융 리포트 · 규제 대응
- 부수 효과: 검증 실패 구간이 **콘텐츠 품질 지표**가 된다 (브레드 0개 = "대사 밀도가 지나치게 높은 편")

**30p ESG** — 2팀의 GOOD AI, 5팀의 ESG 3축 자리
- **E** 온디바이스 추론. 1,000편 규모에서 클라우드 대비 API 호출 3,000회와 데이터 전송이 절감. 재생 시 추론 **0회**
- **S** ① 수동 시청 → 능동 참여 (개입 횟수 **상한**을 설계에 못 박았다 — 많을수록 좋은 구조가 아니다)
  ② 아동 안전 = 환각 차단 ③ 사교육 격차 — 로컬 실행이라 **인터넷이 불안정한 환경**에서도 동작
- **G** 모든 활동이 `타임스탬프 + 원문 인용 + 프레임 ID + 신뢰도 등급` 보유.
  부모 리포트가 "AI가 그렇게 판단했습니다"가 아니라 **"7분 31초 장면의 이 대사에 근거합니다"** 가 된다.
  **폐기된 카드와 그 사유까지 남는다**
