# 부록 — 스토리닷 앱

만 3–7세 아동용 태블릿 앱. 영상을 수동적으로 시청하는 아동을 대상으로 하며, 영상 재생 중 개입해 손으로 하는
인터랙션 활동을 삽입하고 시청 후 이해를 확인한다. 하루 일과가 기기 한 대에서 완결되며 학습까지 연결한다.
보호자가 시간과 활동 종류를 정하고 결과를 리포트로 확인한다.

| | |
| --- | ---: |
| 앱 코드 (JS) | 12,022줄 |
| 서버·도구 (Node) | 2,205줄 |
| AI 모델 | 2종 |
| DB 테이블 | 9개 |
| 화면 | 14종 |

## 1. 프로젝트 개요

| 항목 | 내용 |
| --- | --- |
| 대상 | 만 3–7세. 보호자가 시간과 활동 종류를 설정함 |
| 기기 | Galaxy Tab S8+ · S펜 입력 · 가로 고정 |
| 해결 대상 | 시청이 학습으로 이어지지 않는 구간 — 개입과 응답 유도로 시청 내용을 활동·문항·그리기로 잇고, 그 결과를 리포트로 남김 |
| 구성 | 시청 · 퍼즐 · 국어 · 수학 · 그리기 · 단어장 · 따라 쓰기 · 색칠 · 캐릭터 방 · 리포트 |
| 동작 조건 | 네트워크 없이 전 과정 구동. 외부 호출은 그림 변환 1건 |

**문항은 편마다 자동 선택된다.** 국어 1문항은 작품·월령·시청 순서로, 수학 1문항은 그 편의 활동 후보 중 아동 월령에
가장 근접한 것으로 정해진다. 한 편에서 산출되는 활동 후보는 9–20개다.

**중간 개입은 편당 1회로 제한한다.** 시청 흐름의 단절 비용이 개입 효과를 상회하지 않도록 하드 제약을 두었으며,
문항은 시청을 마친 뒤로 이연한다.

## 2. 핵심 기능과 판정 방식

| 활동 | 형식 | 판정 근거 |
| --- | --- | --- |
| 퍼즐 | 정지 프레임에서 오려낸 조각 끼우기 | 좌표 정합 — 최근접 빈자리 |
| 국어 | 3지선다 — 인물의 동기 · 대사의 의도 | 작품별 문항 뱅크, 오답도 그 편의 실재 요소 |
| 수학 | 3지선다 — 5개 유형, 근거 프레임 동반 | 화면 계수값과 대조 |
| 그리기 · 변환 | 자유 그리기 후 캐릭터로 변환 | 판정 없음 — 산출물 자체가 결과 |
| 단어장 | 낱말을 끌어 아는 것 · 모르는 것으로 분류 | 아동의 자기 보고 — 보호자 리포트에 집계 |
| 따라 쓰기 · 색칠 | 안내선 위 필기 · 선 내부 채우기 | 획이 안내선에 얹힌 비율 |
| 캐릭터 방 | 먹이기 · 쓰다듬기 · 던지기 | 정답 수가 보유 사탕으로 환산됨 |

- **실패 상태를 두지 않는다.** 따라 쓰기·색칠은 아동이 중단하면 버디가 완료하며, 문항은 오답 시 재시도가
  허용된다. 활동이 진행을 차단하지 않도록 설계했다.
- **활동 종류를 데이터로 기술한다.** 편성 데이터만 교체하면 코드 수정 없이 배치가 바뀌며, 보호자가 종류별로
  차단할 수 있다.

## 3. 전체 구조

```
인트로 · 프로필 · 보호자 설정        이름 · 월령 · 하루 시간 예산
        ▼
오늘의 묶음 편성                    plan · 하루 시간 예산 안에서 영상 · 활동 · 미션
        ▼
시청 루프                          0.35초 폴링 · 개입 시각 정합 · 3초 카운트 후 정지
        ▼
중간 개입 — 퍼즐  /  종료 문항 — 국어 · 수학
        ▼
그리기 · 변환 요청                  정사각 PNG · 주제 종류 부착 — 유일한 외부 경로
        ▼
활동 리포트 · 미션                  날짜 · 시청 시간 · 정답 수 · 변환 결과
```

시청·문항·퍼즐·그리기가 하나의 상태 기계에서 구동되며, 활동이 끝나면 정지 지점으로 복귀한다.

### 계층 분리 및 상태 소유

| 계층 | 구성 | 보유 상태 |
| --- | --- | --- |
| 화면 | `screens/` · `ui/` | 표시 상태만. 진행 상태를 보유하지 않음 |
| 활동 | `activities/` | 활동 1건의 진행·판정. 성공 시 호출자에게 반환 |
| 조정 | `App.js` | 라우팅 · 하루 진행 · 정답 누적 |
| 데이터 | `data/` · `assets/*.json` | 작품 · 문항 · 활동 정의. 서버와 동일 스키마 |
| 저장 | AsyncStorage | 프로필 · 설정 · 단어장 · 활동 기록 |
| 외부 | Worker → fal.ai | 무상태. 요청 1건마다 완결됨 |

- **진행 상태를 한 곳에 모은다.** 화면과 활동은 결과만 반환하고 하루 진행은 조정 계층이 단독 보유하므로,
  활동을 추가해도 화면 간 상태 동기화가 발생하지 않는다.
- **서버와 스냅숏이 동일 스키마다.** 오프라인 대체가 별도 코드 경로가 아니라 데이터 출처 교체로 처리된다.

## 7. 서비스 동작 흐름

| # | 단계 | 수행 내용 |
| ---: | --- | --- |
| 1 | 인트로 · 프로필 | 이름·생년월일·성별 입력. 보호자가 하루 사용 시간을 5분 단위로 설정. 형제는 프로필 추가로 분리되며 나이에 따라 문항 세트가 바뀜 |
| 2 | 오늘의 묶음 | 작품 선택 시 당일 시청분과 총 시간이 카드로 제시됨 |
| 3 | 시청 · 개입 | 재생 위치를 0.35초 주기로 감시하다 개입 시각에서 3초 카운트 후 정지. 활동 완료 시 정지 지점에서 재개 |
| 4 | 종료 문항 | 모든 편에서 국어 1문항 · 수학 1문항이 순차 제시됨. 유형이 겹치지 않도록 묶음 단위로 분배 |
| 5 | 그림 · 변환 | 마지막 편 종료 후 그리기. 산출물이 해당 작품 세계의 캐릭터로 변환되어 반환됨 |
| 6 | 리포트 · 미션 | 날짜 · 시청 시간 · 정답 수 · 변환 결과를 한 화면에 정리하고 미션 카드를 제시 |

### 서버 구조 및 오프라인 경로

| 엔드포인트 | 반환 |
| --- | --- |
| `/library` | 작품과 소속 영상 목록 |
| `/videos/:id` | 한 편의 활동 전량 — 문항 · 개입 지점 · 근거 프레임 경로 |
| `/plan` | 당일 묶음. 하루 시간 예산 내에서 영상·활동·미션을 편성 |
| `/sessions` · `/activity-results` | 시청 시간과 문항 결과 기록 |
| `/media/*` | 영상 · 프레임 · 썸네일 |

DB 테이블 — `category` `video` `subtitle` `activity` `child` `session` `plan_session`
`activity_result` `leaves`

```
콘텐츠 서버 응답  →  정상 경로
서버 무응답      →  동봉 스냅숏(library · activities · missions.json) + 기기 media 폴더
                    동일 스키마이므로 분기 1회로 대체됨
```

배포 경로는 서버를 경유하지 않는다. 콘텐츠 서버는 개발 중 편성·검수 용도이며, 기기에는 동일 스키마의
스냅숏이 동봉된다. 변환은 고정 도메인으로 요청하므로 IP가 바뀌어도 수정할 항목이 없다.

## 8. 활동이 도는 원리

### 국어 — 서사 이해 측정

화면의 개수가 아니라 서사 이해를 측정한다. 해당 작품의 편을 근거로 작성된 문항 뱅크에서 시청 순서대로 선택하며,
오답도 그 편에 실재하는 요소로 구성하므로 영상을 보지 않은 상태에서는 선택할 수 없다.

### 수학 — 근거 프레임 동반

| 유형 | 질문 형태 |
| --- | --- |
| 개수 세기 | 화면 내 동일 대상의 수량 |
| 모두 세기 | 두 집합의 합산 |
| 수 가르기 | 전체에서 부분의 분할 |
| 크기 비교 | 두 대상의 대소 판정 |
| 모양 찾기 | 제시 형태와 동일한 대상 탐색 |

- **동일 유형의 연속 배치를 금지한다.** 두 번째 문항부터는 계수하지 않고 문장 형태만으로 응답하는 양상이
  관측되어, 묶음 내 유형을 강제 분산한다.
- **근거 프레임을 동반 제시한다.** 12분 전 기억이 아니라 제시된 화면에서 계수하도록 설계해 회상 부담을
  제거했다.
- 편당 9–20개의 활동 후보 중 아동 월령에 가장 근접한 항목이 선택되므로, 같은 편도 아이마다 다른 문항이 제시된다.

### 퍼즐 — 프레임에서 오려낸 조각

```
개입 시각 도달 → 3초 카운트 → 화면 정지
   해당 프레임 = 퍼즐 판 (대상 영역 결손)
   조각 = 동일 프레임에서 오려낸 것
   조각 안착 → 정지 지점에서 재생 재개
```

- **조각을 별도로 그리지 않는다.** 개입 지점의 프레임에서 대상만 분리하며, 조각과 결손부가 동일한 베지어
  윤곽을 공유하므로 경계가 어긋나지 않는다.
- **2배 해상도로 오린 뒤 축소한다.** 픽셀 단위로 절단하면 가장자리에 계단이 남으므로, 축소로 그 계단을
  반투명하게 소거한다.
- **조각은 축소하고 결손부는 확대한다.** 동일 마스크를 양쪽에 쓰면 조각에 배경색이 혼입되거나 판에 윤곽선이
  잔류한다.
- **판이 영상 영역을 그대로 점유한다.** 여백이 생기면 영상에서 퍼즐로 전환된 것이 인지되므로, 정지 화면과
  동일한 크기로 배치한다.

## 9. 그림 변환

### 처리 규칙

그림은 정사각으로 패딩해 전송한다. 사물은 입력 선을 보존한 채 정리하고, 캐릭터는 몸 비율·얼굴 배치·눈
구조의 종족 규칙이 입력 형태를 상회한다. 아이 그림에서 계승하는 항목은 색과 머리 모양으로 한정한다.

### 모델 이원화

| 구분 | 사물 그림 | 캐릭터 그림 |
| --- | --- | --- |
| 모델 | `fal-ai/flux-kontext/dev` | `fal-ai/nano-banana/edit` |
| 계열 | 확산 편집 | Gemini Flash Image |
| 입력 선의 취급 | 원위치 보존 후 정리 | 형태 규칙이 선을 상회 |
| 아이 그림에서 계승 | 윤곽 전체 | 색 · 머리 모양 |
| 지시 준수도 | 세부 규칙 미반영 | 비율 · 배치까지 반영 |

- **단일 프롬프트가 불가능한 구조다.** 사물에 유효한 "선을 지켜라"가 캐릭터에서는 낙서를 낙서로 잔존시킨다.
  주제 종류를 앱이 전달하고 워커가 분기한다.
- **부정 지시는 역효과를 낸다.** "동물이 아님" 류의 부정문은 확산 모델에서 해당 대상을 오히려 유도하므로
  전량 제거하고 긍정 규칙만 기술했다.
- **형태 규칙을 고정한다.** 머리가 전신의 3/4, 눈높이는 머리 높이의 60% 지점 등 종족 규칙을 명시해 회차 간
  편차를 억제한다.
- API 키는 워커에만 둔다 — APK는 역어셈블이 가능하다.

## 10. 활동 외 화면

| 화면 | 구성 및 설계 의도 |
| --- | --- |
| 메인 | 별을 누르면 마이 캐릭터 · 부모 리포트 · 설정으로 분기. 인사 음성은 메인 최초 진입 시 1회만 재생하며, 영상에서 복귀할 때는 재생하지 않음 |
| 캐릭터 방 | 사탕 10개를 초기 보유하고 정답 시 누적됨. 먹이기·쓰다듬기·던지기 반응으로 활동과 보상을 한 화면에서 연결 |
| 단어장 | 낱말을 끌어 분류. 미숙지 낱말은 보호자 리포트에 집계 |
| 따라 쓰기 · 색칠 | 획이 안내선에 얹힌 비율로 통과를 판정. 색칠은 선 내부만 채워짐 |
| 활동 리포트 | 날짜 · 시청 시간 · 정답 수 · 변환 결과를 단일 화면에 배치하고 미션 카드로 종료 |

### 보호자 영역 · 입력 · 음성

| 항목 | 값 |
| --- | --- |
| 보호자 리포트 진입 | 셈 문제 통과 시 |
| 하루 사용 시간 설정 | 5분 단위 |
| 활동 종류별 차단 | 퀴즈 · 그림 · 퍼즐 |
| 아이 프로필 | 추가 · 전환 · 전량 삭제 |
| 초기 보유 사탕 | 10개 |

- **보호자 화면을 문으로 분리한다.** 간단한 셈 문제를 통과해야 열리므로 아동의 우발적 진입이 차단된다.
  안에는 주간 자립 순간·관심사·활동 요약과 미숙지 낱말이 집계된다.
- **입력 정책을 지점 수로 고정한다.** 1지점은 항상 펜, 2지점은 확대·이동이므로 필기 중 화면이 밀리지 않는다.
  펜 접촉 직후 손가락 입력을 무시해 손바닥 오입력을 차단하고, S펜 버튼 입력은 지우개로 전환한다.
- **음성은 작품 단위로 고정한다.** 한 편 안에서 화자가 바뀌면 발화 주체를 식별하지 못하므로 작품별 목소리를
  유지하며, 동시 발화 구간은 슬롯을 분리해 병렬 재생한다.

## 11. 개발 과정의 시행착오

### 초기 설계 한계 및 개선

| 초기 구현 | 관측된 결과 | 변경 |
| --- | --- | --- |
| 부정형 프롬프트 | "동물이 아님"을 명시할수록 동물이 생성됨 | 부정문 전량 제거 · 긍정 규칙만 기술 |
| 편집 모델 단일 사용 | 비율·배치 등 세부 지시가 반영되지 않음 | 캐릭터만 지시 준수형 모델로 분리 |
| 조각과 구멍에 동일 마스크 | 조각에 배경색 혼입 · 판에 윤곽 잔류 | 조각은 축소 · 구멍은 확대 |
| 원본 해상도 절단 | 가장자리에 계단이 남아 합성 티가 남 | 2배로 오린 뒤 축소 |
| 퍼즐을 카드 내부에 배치 | Android에서 렌더링되지 않음 | 별도 레이어 + 측정 좌표로 중첩 |
| 판을 contain 으로 맞춤 | 좌우 여백이 남아 전환이 인지됨 | 영상이 점유하던 칸을 그대로 채움 |

**공통 원인은 검증 시점이었다.** 위 항목은 모두 코드 검사로 검출되지 않고 실기기 화면에서만 확인되는
종류이므로, 화면 산출물을 매 회차 육안 확인하는 절차를 두었다.

### 빌드 · 환경 실패 사례

| 증상 | 원인 | 대응 |
| --- | --- | --- |
| CMake 중단 | JDK 25의 제한된 메서드 호출 차단 | JDK 21 고정 |
| 번들 단계 무한 대기 | 개발 서버가 8081 점유 시 릴리스 번들러가 포트 확보 실패 | 빌드 전 8081 해제 |
| 리소스 파싱 실패 | 동기화가 생성한 중복 파일 `* 2.xml` | 빌드 전 일괄 삭제 · 364개 |
| 리소스 중복 정의 | 교체 후 잔존한 구 확장자 음원 | 생성물 정리 |
| 설치 거부 | 로컬 빌드와 배포본의 서명 불일치 | 개발 클라이언트는 단일 경로로만 갱신 |

- **정적 검사로 검출되지 않는 회귀가 존재한다.** 재생 종료 상태를 다음 편에서 초기화하지 않아 두 번째 영상이
  표시되지 않은 사례가 있었으며, 검사는 통과했고 실기기 재생에서만 드러났다.
- **기기에서만 확인되는 항목을 분리한다.** 필기 입력·영상 렌더링·변환 결과는 에뮬레이터에서 재현되지 않으므로
  실기기 확인 절차로 분리했다.

## 12. 차후 개발

| 항목 | 현재 | 다음 |
| --- | --- | --- |
| 음성 인식 | 말하기 활동이 `-35dB` 문턱을 일정 시간 넘겼는지로 판정. 발화 내용은 대조하지 않음 | 발화 내용 대조 — 말로 답하는 문항 · 따라 읽기 |
| 활동 기록 | 기기 내부 누적. 서버 기록 경로는 열려 있음 | 기간별 추이 — 무엇이 늘고 무엇이 정체됐는지 |

- **말하기 활동은 이미 무대에 있다.** 마이크 입력을 받아 통과를 판정하는 경로가 구동 중이므로, 음성 인식은 새
  활동을 만드는 것이 아니라 판정 근거를 음량에서 내용으로 올리는 것이다.
- **적용 대상이 셋으로 늘어난다.** 말하기 활동의 낱말 대조, 국어 문항의 구술 응답(선택지 없이 답하기), 자막
  구간 따라 읽기.
- **기존 판정 규칙은 유지된다.** 파열음·숨에서 나는 짧은 끊김을 무시하는 구간 판정은 인식 결과의 전처리로
  그대로 쓰인다.

### 음성 인식 경로 비교

| 기준 | 온디바이스 | 서버 |
| --- | --- | --- |
| 오프라인 원칙 | 유지됨 | 네트워크 필요 |
| 아동 음성 | 기기 밖으로 나가지 않음 | 외부 전송 · 보호자 동의와 저장 정책 필요 |
| 응답 지연 | 즉시 | 왕복 지연 발생 |
| 운영 비용 | 없음 | 호출당 과금 |

**본 앱의 전제는 기기 한 대에서의 완결이다.** 그 전제를 지키려면 온디바이스가 기본이 되고, 서버는 인식이 반복
실패한 구간에 한해 보조로 두는 구성이 맞다. 판정은 통과·실패로 이분하지 않는다 — 인식이 어긋나도 활동은
진행되며, 버디가 발음을 다시 들려준다. 실패 상태를 두지 않는 기존 원칙과 같다.
