# 스토리닷 — 진행상황 / 핸드오프

작성: 2026-08-18. 이 문서 + `~/.claude/.../memory/`(자동로드) + 코드/git = 세션 간 연속성.

## 개요
- 앱: 스토리닷(StoryDot, 구 PATTI). 4~6세 안드로이드 태블릿(가로 고정) AI 인터랙티브 미디어.
- 코드: `patti-app` (Expo SDK 57, RN 0.86). 프런트는 `frontend/`, 서버는 `backend/`.
- 변환 서버: **Cloudflare Worker** `backend/worker` → fal.ai. (2026-08-31 갱신. 그 전에는 로컬 5055 서버 + Gemini 직결이었으나 폐기했다 — 노트북 없이 돌아야 해서 클라우드로 옮겼고, fal 키는 워커 시크릿에만 둔다. APK는 뜯어볼 수 있다.)
  - 사물 그림 `fal-ai/flux-kontext/dev` — 아이 선을 그 자리에 두고 다듬는 편집 모델.
  - 캐릭터 그림 `fal-ai/nano-banana/edit` — 지시를 잘 따라 종족 규칙(몸 비율·얼굴 배치)이 지켜진다.
  - 배포는 `cd backend/worker && npx wrangler deploy`.
- **개발빌드로 전환 완료** (Expo Go 아님). Skia/Rive/reanimated 네이티브 포함.

## 핵심 gotcha (새 세션 필독)
- **metro는 8081 하나만.** 중복 뜨면 번들 깨짐("transformFile undefined"류). `lsof -ti:8081` 확인. 사용자에게 `expo start` 새로 돌리지 말라 안내.
- **오버레이 중앙정렬 = Modal + useWindowDimensions 명시 width/height.** `absoluteFill`은 네이티브영상 레이아웃 때문에 반쪽만 덮음. (교훈 메모리 있음)
- ~~LAN IP 하드코딩~~ 해소. 변환은 고정 주소(`storydot-character.falai.workers.dev`)로 가므로 네트워크가 바뀌어도 손댈 것이 없다. 콘텐츠 서버(5056)만 `adb reverse` 로 잇는다.
- **iOS 로컬빌드 실패**(Xcode 26.2): ① expo-modules-jsi Swift `abs`→`.magnitude` 패치(node_modules 직접, **patch-package로 영속화 필요!**) ② codesign detritus. → **EAS 클라우드 빌드로 우회**(iOS 시뮬 profile: eas.json development.ios.simulator=true).
- **동시 빌드 금지**(build.db 잠김). 한 번에 하나.
- reanimated 4.5.1 필요(Skia 의존), `babel.config.js`에 `react-native-worklets/plugin`, `babel-preset-expo` 설치됨.

## 차후 계획 — 그림판 완성도 (S-Note/GoodNotes급)
드롭인 "굿노트 SDK"는 없음. 두 축:

### A. Skia 폴리시 (크로스플랫폼, 현 dev build에서)
1. ~~PanResponder → react-native-gesture-handler~~ **완료**: RNGH 2.32.0 설치, `SketchPad`가 `Gesture.Pan().runOnJS(true).minDistance(0).maxPointers(1)` + `GestureDetector` 사용. App 루트에 `GestureHandlerRootView`. 좌표는 `event.x/y`(뷰 기준).
2. ~~팜리젝션~~ **완료**: `pointerType !== TOUCH`(스타일러스/지우개촉) 접촉 시각 기록 → 그 뒤 `PALM_REJECT_MS`(1500ms) 안에 들어온 finger 터치는 무시. 창 밖이면 손가락 그리기 정상.
   - 필압도 RN `nativeEvent.force`(안드로이드 미제공) → RNGH `event.stylusData.pressure`로 교체. 없으면 `velocityX/Y` 속도→굵기 폴백.
   - **네이티브 재빌드 필요**(RNGH 신규 네이티브 모듈). 실제 검증은 S-Pen 태블릿 실기기에서.
3. **필압 커브 튜닝**: perfect-freehand `thinning/streamline/smoothing` + 속도→굵기 커브 조정.
4. **틸트/방위**: Android MotionEvent AXIS_TILT — RN 기본 미노출 → 네이티브/gesture-handler 필요.
5. undo/redo, 레이어.

### B. S-Pen SDK (네이티브 안드로이드, 삼성)
- **S-Pen 버튼→지우개**: MotionEvent `buttonState`(BUTTON_STYLUS_PRIMARY) 또는 `toolType`(TOOL_TYPE_ERASER) 감지 필요. RN nativeEvent에 없음.
- **방법**: 작은 **Expo Native Module(Kotlin)** 작성 — 터치 View를 래핑해 toolType/buttonState/tilt/pressure를 JS로 방출. SketchPad가 PanResponder 대신 이걸 사용.
- 삼성 "S Pen Remote SDK"는 버튼 원격용(에어액션). 펜 입력 자체는 표준 MotionEvent로 충분.

### 권장 순서
1. gesture-handler 도입(팜리젝션+저지연) — 네이티브 재빌드 1회.
2. Expo Native Module로 toolType/buttonState 노출 → 버튼=지우개.
3. perfect-freehand 파라미터 튜닝으로 필기감.
→ 새 세션에서 이 문서 읽고 A1부터. 각 단계 EAS 빌드 필요.
