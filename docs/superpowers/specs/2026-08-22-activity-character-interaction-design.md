# 활동 중 캐릭터 상호작용 설계

작성일: 2026-08-22
대상: Story Dot (`com.flyai.patti`) — 만 3~5세 태블릿 앱

## 배경

영상 중간에 뜨는 활동이 지금은 4지선다 퀴즈 하나뿐이다. 캐릭터는 말풍선 옆에
붙은 정지 이미지고, 반응은 카드 흔들림과 텍스트뿐이다. 글자를 못 읽는 아이는
문제 자체를 알 수 없고, 오답 처리가 "틀렸다"로 읽혀 위축된다.

이 설계는 두 가지를 바꾼다. 캐릭터를 **문제를 내는 친구**로 만들고, 4지선다
비중을 줄여 **몸으로 참여하는 활동** 넷을 새로 넣는다.

## 목표

- 캐릭터가 묻고, 아이 동작에 반응하고, 화면 위를 움직인다
- 글자를 전혀 못 읽어도 활동이 성립한다 (말풍선 + 목소리가 항상 짝)
- 아이가 틀릴 수 없다 — 오답 처리 없음, 막히면 캐릭터가 풀어준다
- 활동을 하나 더 만들 때 캐릭터 코드를 건드리지 않는다

## 범위 밖

- 기존 `QuizOverlay`(16종 퀴즈) 제거 — DB에 데이터가 남아 있어 그대로 둔다
- 음성인식(STT) — 아래 "따라 말하기" 항목의 판정 방식 참고
- 리포트 축소, UI 유아화, 개입 타이밍 조정 — 별도 업무로 분리

## 화면 골격

**B 뼈대 + 선택적 C 이동.** 캐릭터의 기본 자리는 화면 아래이고, 활동이 좌표를
넘길 때만 그 지점으로 올라가 움직인다. 좌표를 안 넘기면 아래에 머문다.

활동 4종 모두 이동을 쓴다.

| 활동 | 캐릭터가 가는 곳 |
|---|---|
| ① 찾아 짚기 | 아이가 맞게 짚은 지점 |
| ② 끌어다 놓기 | 놓을 자리의 **반대편** (손가락 경로를 가리지 않으려고) |
| ③ 세어보기 | 방금 센 사물 위 |
| ④ 따라 말하기 | 마이크 원 옆 (소리 크기에 따라 살짝 커짐) |

## 활동 4종

### ① 찾아 짚기 (`findit`)

영상의 한 장면을 보여주고 "하츄핑 어디 있지?"라고 묻는다. 아이가 맞는 자리를
짚으면 동그라미가 뜨고 캐릭터가 날아가 "찾았다!". **빗나가면 아무 반응이 없다** —
틀림 표시 없이 계속 짚게 둔다.

장면 그림은 퍼즐과 같은 방식으로 만든다. `backend/server/tools/puzzle-frames.mjs`가
이미 트리거 시각의 프레임을 ffmpeg으로 뽑아 쓰므로, 같은 도구를 `findit`까지
확장한다.

### ② 끌어다 놓기 / 짝 맞추기 (`drag`)

사물을 집어 제자리에 놓는다 (모자를 머리에). 놓을 자리 근처면 쏙 빨려들어가고
(스냅), 엉뚱한 데 놓으면 제자리로 튕겨 돌아온다. 실패가 아니라 "아직"으로 읽힌다.

### ③ 세어보기 (`count`)

"사과 몇 개지?" 하나 탭할 때마다 캐릭터가 그 위로 폴짝 옮겨가며 소리 내어 센다.
다 세면 "네 개였네!". 숫자를 고르는 게 아니라 **세는 행위 자체가 활동**이다.

### ④ 따라 말하기 (`say`)

캐릭터가 단어를 말하면 아이가 따라 한다. 마이크가 5초 열리고, **음량이 기준치를
넘어 0.4초 이상 지속되면 통과**한다. 조용하면 "안 들렸어~ 한 번 더!" 하고 다시
기다린다.

정오 판정을 하지 않는다. STT는 성인 발음으로 학습돼 유아 발음 정확도가 크게
떨어지고, "사과"를 "아과"로 말하는 정상 발달을 오답 처리한다. 목적이 발음 채점이
아니라 입을 떼게 하는 것이므로 **발화 감지로 충분하다**. 이 선택은 데모에서
"음성인식이 아니라 발화 감지"라고 설명할 수 있어야 한다.

`expo-audio`의 녹음 metering을 쓴다. 네이티브 모듈 추가가 없으므로 재빌드가
필요 없고 오프라인에서 동작한다.

## 판정 · 재시도 규칙

**아이는 못 틀린다. 다만 못 끝낼 수는 있다.**

| 활동 | 맞았을 때 | 빗나갔을 때 |
|---|---|---|
| 찾아 짚기 | 동그라미 + 캐릭터 이동 | 무반응 |
| 끌어다 놓기 | 스냅 + 캐릭터가 가리킴 | 제자리로 튕김 |
| 세어보기 | 캐릭터 이동 + 숫자 셈 | 같은 걸 또 탭하면 무시 |
| 따라 말하기 | 막대 참 + 통과 | "한 번 더" |

### 힌트 사다리

아무 동작이 없을 때 시간이 지나면 캐릭터가 단계적으로 돕는다.

- **8초** — 정답 쪽을 쳐다본다 (말 없이)
- **16초** — 정답 근처로 가서 콩콩 뛴다
- **24초** — 캐릭터가 대신 풀고 "여기 있었네!" → **성공으로 처리하고 넘어간다**

24초에서 넘어가는 것이 핵심이다. 유아는 못 푸는 문제 앞에서 금방 흥미를 잃고,
붙잡아두면 영상 자체를 싫어하게 된다. 막히면 캐릭터가 풀어주고 같이 기뻐하는
것으로 끝낸다.

**"건너뛰기" 버튼은 두지 않는다.** 유아는 그게 뭔지 모르고, 부모가 대신 누르면
아이 경험이 잘린다.

## 멘트 · 음성

멘트 한 줄은 **글자 + 소리 한 쌍**이다. 코드가 문자열을 직접 들고 있으면 목소리
파일이 올 때마다 코드를 고쳐야 하므로, 대사를 데이터로 분리한다.

```json
// frontend/assets/lines.json  — 글자는 캐릭터 공용
{
  "quiz.ask":     ["이건 뭘까?", "우리 같이 맞혀볼까?", "음~ 뭐지?"],
  "answer.right": ["우와 맞았어!", "역시 대단해!", "딩동댕!"],
  "answer.again": ["음~ 다시 볼까?", "거의 다 왔어!", "한 번만 더!"],
  "count":        ["하나", "둘", "셋", "넷", "다섯",
                   "여섯", "일곱", "여덟", "아홉", "열"],
  "speak.listen": ["따라 해볼까?", "네 차례야!"],
  "speak.quiet":  ["안 들렸어~ 한 번 더!", "조금만 크게!"]
}
```

목소리 파일은 같은 이름 규칙으로 얹되 **캐릭터별 폴더**로 가른다.

```
frontend/assets/voice/bunny/answer.right.1.m4a
frontend/assets/voice/dino/answer.right.1.m4a
```

**파일이 없으면 글자만 나가고 앱은 정상 동작한다.** 목소리는 나중에 폴더에 넣기만
하면 되고 코드는 손대지 않는다.

랜덤은 **직전에 쓴 것을 제외**한다. 3개짜리에서 같은 게 연속으로 나오면 여러 벌인
티가 나지 않는다.

캐릭터는 **활동 시작 시 둘 중 하나를 뽑고, 그 활동이 끝날 때까지 바꾸지 않는다.**
문장 중간에 목소리가 바뀌면 아이가 혼란스러워한다.

### 녹음 목록 (캐릭터당 23개, 총 46개)

| 상황 | 파일명 | 개수 |
|---|---|---|
| 문제 낼 때 | `quiz.ask.1` ~ `.3` | 3 |
| 정답 | `answer.right.1` ~ `.3` | 3 |
| 다시 하기 | `answer.again.1` ~ `.3` | 3 |
| 숫자 세기 | `count.1` ~ `.10` | 10 |
| 따라 말하기 유도 | `speak.listen.1` ~ `.2` | 2 |
| 소리 안 났을 때 | `speak.quiet.1` ~ `.2` | 2 |

문제별 질문 음성은 지금처럼 DB의 `audioUrl`로 계속 간다.

## 코드 구조

`App.js`는 이미 6,400줄이다. 활동 4종을 여기 넣으면 손댈 수 없게 되므로 새 파일로
뺀다.

```
frontend/
  activities/
    ActivityStage.js   공용 뼈대: 캐릭터·말풍선·힌트 사다리
    Buddy.js           캐릭터 하나. 이동·반응 애니메이션만 안다
    FindIt.js          ① 찾아 짚기
    DragMatch.js       ② 끌어다 놓기
    CountIt.js         ③ 세어보기
    SayIt.js           ④ 따라 말하기
  lines.js             멘트 뽑기 + 캐릭터별 음성 재생
  assets/lines.json
  assets/voice/bunny/  assets/voice/dino/
```

`App.js`가 하는 일은 트리거 시각에 `<ActivityStage>`를 띄우는 것뿐이다. 지금
`QuizOverlay`가 뜨는 자리를 그대로 쓴다.

### 활동이 지키는 계약

활동은 캐릭터를 **그리지 않고 시키기만 한다.**

```js
buddy.say('answer.right')      // 말풍선 + 목소리, 멘트는 알아서 랜덤
buddy.moveTo({ x, y })         // 그 좌표로 폴짝 (0~1 비율)
buddy.home()                   // 아래 제자리로
buddy.react('right' | 'again') // 뛰기 / 고개 갸웃
```

이 네 개가 전부다. 활동을 하나 더 만들 때 캐릭터 코드는 한 줄도 건드리지 않는다.

### 힌트 사다리는 ActivityStage만 가진다

활동은 "정답이 화면 어디냐"만 알려준다.

```js
<FindIt hintAt={{ x: 0.72, y: 0.31 }} onSolve={…} />
```

8·16·24초 타이머, 쳐다보기, 콩콩, 대신 풀어주기가 뼈대에 한 벌만 있다. 활동
4종이 각자 타이머를 굴리면 반드시 어긋난다.

## 활동 데이터

`frontend/assets/activities.json`에 타입 4종을 추가한다. 좌표는 **0~1 비율**이라
해상도가 달라도 깨지지 않는다.

```json
{ "type": "findit", "at_sec": 27,
  "payload": { "image": "teenieping-01-27",
               "target": { "x": 0.72, "y": 0.31, "r": 0.09 },
               "ask": "하츄핑 어디 있지?" } }

{ "type": "drag",  "at_sec": 55,
  "payload": { "item": "hat", "slot": "head", "scene": "teenieping-01-55" } }

{ "type": "count", "at_sec": 136,
  "payload": { "item": "apple", "n": 4 } }

{ "type": "say",   "at_sec": 175,
  "payload": { "word": "사과", "listenMs": 5000 } }
```

## 기존 코드에 손대는 곳

- `frontend/sound.js` — `speak()` / `speakUrl()` 첫 줄의 `return;` 제거,
  `speakLine(character, key)` 추가
- `frontend/App.js` — 트리거 분기에 타입 4종 연결. `QuizOverlay`는 남긴다
- `backend/server/tools/puzzle-frames.mjs` — `findit` 타입도 프레임을 뽑도록 확장

## 확인 방법

- 목소리 파일이 하나도 없는 상태에서 활동 4종이 전부 끝까지 진행된다
- 아무 동작 없이 24초를 두면 캐릭터가 대신 풀고 다음으로 넘어간다
- 활동 한 번에 캐릭터가 바뀌지 않는다
- 같은 반응 멘트가 연속으로 두 번 나오지 않는다
