# 사건 기반 퀴즈 지점 추출 — 설계

**작성일** 2026-08-28
**상태** 설계 승인, 구현 전
**대상 파일** `events.py`(신규) · `skills/events/SKILL.md`(신규) · `storydot.py` · `skills/quiz/SKILL.md` · `scan.py`

---

## 1. 왜 하는가

2026-08-27 심사 피드백에서 두 가지가 나왔다.

- 참석자 7 — "토끼와 거북이에서 토끼가 졌잖아. 그러면 토끼가 거기서 **'내가 왜 졌을까?'** 하고 질문하면 되지. 생뚱맞게 박스 쳐놓고 물어보면 이게 뭔지 판단이 안 돼."
- 참석자 1 — "그건 엄청 단순한 레벨이고, 레벨 2·3 갈수록 결국 **컨텍스트를 얼마나 이해하고 답변하는 건가**. 뭐 때문에 이런 것들이 발생했냐, 그런 **추론 영역**까지 가도록 해야 된다."

두 지적이 같은 곳을 가리킨다. 지금 파이프라인은 **사건을 모른다.**

### 측정한 사실

전편 스캔(`scan.py`, 5편)으로 확인했다.

| 작품 | 개입 가능한 자리 | act 경계 | 최종 채택 |
| --- | ---: | ---: | ---: |
| 타요1화 | 511 | 5 | 1 |
| 뽀로로1화 | 615 | 6 | 2 |
| 아기상어1화 | 521 | 4 | 2 |
| 티니핑1화 | 431 | 9 | 2 |
| 브레드1화 | 604 | 5 | 0 |

화면이 앉고 소리가 빈 자리는 영상의 33~65%다. 병목은 서사 게이트(act 경계)다.

그런데 **그 act 경계가 사건이 아니다.** 타요1화의 내레이션 8개는 전부 장면 표지다.

```
114.6  조금씩만 양보하면 금방 지나갈 수 있어요!
223.1  며칠 뒤, 고마 버스들이 ...를 보고 있어요.        ← 시간 경과
283.5  시간이 흘러 구조대 선발대회 날이 되었어요.         ← 시간 경과
506.7  드디어 선발대회 막 열렸네요!                    ← 장면 시작
567.0  모두 오래 기다리셨습니다                        ← 장면 시작
```

"이제 다음 장면입니다"이지 "무슨 일이 있었습니다"가 아니다. 내레이터가 없는 티니핑은 `beats.py`가
경계 9개를 뽑지만 라벨이 `출발` · `아무렴 출발` · `피타임` · `사포핑·마법` — 토픽 키워드다.
`find_acts` 주석이 이미 자백해 뒀다: *"무엇이 끝났는지 알 수 없어 퀴즈 근거로 못 쓴다."*

물을 사건을 모르니 화면에서 셀 수 있는 것을 셀 수밖에 없다. 생성된 활동 26건이 레벨 1에 몰린 이유다.

### 목표

사건을 1급 개념으로 만들고, 개입지점을 **사건에서** 만든다.
성패 지표는 개입지점 개수가 아니라 **`kind` 분포** — `결과`·`갈등` 사건이 실제로 잡히는가.

## 2. 사건의 계약

`events.py` 가 정본 전사본을 `claude` CLI 1프로세스에 넘겨 사건 목록을 받는다.
계약은 `skills/events/SKILL.md`. 호출 방식은 `generate.py` 의 `_claude()` 패턴을 그대로 쓴다
(`--append-system-prompt` 로 SKILL.md 주입, `storydot.claude_result()` 로 봉투 열기).

### 스키마

```json
{"id": "e03",
 "what": "타요가 구조대 선발대회에서 탈락했다",
 "who": "타요",
 "kind": "결과",
 "evidence": ["s142", "s143", "s147"]}
```

| 필드 | 규칙 |
| --- | --- |
| `id` | `events.py` 가 부여. LLM 이 정하지 않는다 |
| `what` | 한 문장. 사건의 서술 |
| `who` | 사건의 주체. 모르면 `null` |
| `kind` | `결과` · `감정` · `시도` · `발견` · `갈등` **다섯 개로 닫는다** |
| `evidence` | 정본 세그먼트 id 배열. **1개 이상** |

**`t` 는 스키마에 없다.** 시각은 LLM 이 정하지 않고 `events.py` 가 계산한다 —
`t = max(canon[id].t1 for id in evidence)`. 사건이 끝난 시각이다.
이 코드베이스는 이미 같은 교훈을 두 번 겪었다(이름 대표형 자동 확정 실패, 앵커 없는 수치 불신).
LLM 에게 초를 물으면 지어낸다.

`kind` 를 닫는 이유: 열어 두면 매 호출마다 새 범주가 생겨 하류에서 분기를 못 짠다.
다섯 개는 참석자 1 의 레벨과 대응한다 — `결과`·`갈등` → 레벨 3(왜?), `감정` → 레벨 2, `발견`·`시도` → 레벨 1~2.

### LLM 에 주는 것

정본 세그먼트 중 `conf` 가 `high` / `medium` 인 것만. `id` · `t0` · `t1` · `text` · `conf`.
`quarantine` 은 제외한다.

**프레임은 주지 않는다.** 사건은 대사에서 나온다. 화면은 지점 스냅과 활동 생성에서 쓴다.

## 3. 결정적 게이트

`activities.py` 구조를 복제한다. LLM 합의와 무관하며, 실패는 재시도가 아니라 **폐기**다.

| # | 검사 | 실패 시 |
| --- | --- | --- |
| ① | `evidence` 의 모든 id 가 정본에 실재하는가 | 폐기 |
| ② | 그 세그먼트 `conf` 가 전부 `high`/`medium` 인가 | 폐기 |
| ③ | `who` 가 확정 이름 사전 또는 근거 세그먼트 원문에 있는가 | **`who=null` 로 강등** |
| ④ | `what` 의 내용어가 근거에서 도출되는가 | 폐기 |
| ⑤ | 근거 세그먼트의 시간 스팬이 `RECALL_WINDOW`(100초) 이내인가 | 폐기 |
| ⑥ | `kind` 가 허용된 다섯 개 중 하나인가 | 폐기 |

③만 강등인 이유: 화자를 특정 못 해도 사건 자체는 유효하다. 캐릭터 매개 개입을 못 쓸 뿐이다.

④는 `grounding.py` 의 `GROUNDED_RATIO` 를 재사용한다. 용언 활용을 못 잇는 한계
(`찾았어요` ↔ `찾아줬잖아`)를 그대로 물려받는다 — 과폐기 쪽으로 기울어 있어 안전한 방향이다.

⑤의 근거는 이미 코드에 있다. `evidence()` 의 `RECALL_WINDOW` 주석: *"유아는 그만큼 거슬러
기억하지 못한다."* 3분 떨어진 대사 둘을 묶어 사건이라 우기는 것을 막는다.

## 4. 사건 → 개입지점

후보 생성원이 `acts` 에서 `events` 로 바뀐다. 그 아래(정착 → 점수 → 선택)는 그대로다.

### snap_forward

`snap_back()` 은 더 큰 공백을 찾아 **과거로** 당긴다. 사건에는 쓸 수 없다 —
"타요가 탈락했다" 사건 한복판으로 당기면 사건이 아직 안 끝났다.

새 함수 `snap_forward(t, canon, end, pad, look=20.0)` — 사건 `t` 이후 20초 안에서 안전한 자리를 찾는다.
20초 안에 자리가 없으면 그 사건은 버린다(기각 사유를 남긴다).

`look=20.0` 인 이유: `visual.extract_evidence_frames(video, t, span=20.0)` 가 이미 쓰는 창이다.
같은 창을 쓰면 프레임 근거와 사건이 겹치고 새 상수가 늘지 않는다.

### 근거 개수 임계 — min_evidence 를 낮춘다

**이걸 안 고치면 사건이 전멸한다.** 현재 `min_evidence = 5` 는 "개입 직전 100초에서 긁어모은
대사가 5건 이상"이라는 뜻이다. 긁어모으는 방식이라 5건이 쉽게 찬다.

사건이 지목한 근거는 다르다. "타요가 탈락했다"는 보통 2~3개 세그먼트로 성립한다.
같은 임계를 그대로 쓰면 정상 사건이 전부 폐기된다.

→ 사건 경로의 임계를 `EVENT_MIN_EVIDENCE = 2` 로 새로 둔다. `params()` 의 `min_evidence` 는
남기되 사건 경로에서는 쓰지 않는다.

이 값은 **눈금이다.** 2로 시작하되 1차 실측에서 환각 사건이 섞여 들어오면 올린다.
근거 1건짜리 사건은 "누가 그렇게 말했다" 수준이라 되물을 게 없을 가능성이 높다.

### 점수

**`pick_score()` 의 가중치와 항은 안 바꾼다.** `n_ev` 를 "사건이 지목한 근거 개수"로 재해석한다.
다만 정규화 기준을 `min_evidence`(5) 에서 `EVENT_MIN_EVIDENCE`(2) 로 바꿔야 한다 —
`_sat(n_ev - 2, 2)` 가 되어 근거 2건은 0점, 4건 이상이면 만점이다.
이걸 안 바꾸면 근거 항이 사실상 항상 0점이 되어 죽은 항이 된다.

`kind` 별 가중은 **넣지 않는다.** 어느 `kind` 가 더 좋은 퀴즈를 낳는지 아직 데이터가 없다.
레벨 분포를 관측한 뒤에 정한다.

### acts 의 처지

`acts` 는 남긴다. 엔딩 판정과 보고에 계속 쓰이고, **후보 생성에서만 빠진다.**

## 5. 파이프라인 단계 재편

지금 `storydot.py` 는 LLM 을 부르지 않는다. 정본·act·개입지점을 전부 순수 파이썬으로 낸다.
사건 추출을 그 안에 넣으면 그 성질이 깨진다. 그래서 개입지점 산출을 `events.py` 로 **옮긴다.**

```bash
python3 storydot.py 영상.mp4           # ① 정본 + act              LLM 없음
python3 events.py work/X_plan.json     # ② 사건 + 개입지점          claude 1프로세스
python3 generate.py work/X_plan.json   # ③ 활동 생성·검증           claude 2프로세스
```

부수 효과로 34KB 짜리 `storydot.py` 가 가벼워진다.

### storydot.py 에서 events.py 로 옮기는 것

```
interrupt_points()   후보 생성. 생성원이 acts → events 로 바뀐다
snap_back()          → snap_forward() 로 대체
settle()             정착 (motion 의존)
choose()             선택
pick_score() / _sat  점수
PICK_W / SHOT_BONUS  가중치
CLOSEUP_REL          샷 크기 임계
detail_baseline()    작품별 디테일 기준선
evidence()           사건이 지목한 id 를 쓰도록 바뀐다
params() 중 개입 관련 키 (min_start · min_gap · max_activities · speech_pad)
```

`storydot.py` 에 남는 것: 인제스트 · ASR · 정본 구축 · 이름 사전 · `find_ending` · `find_acts`.
즉 **"영상에서 정본과 장 구조를 뽑는 것"** 까지다.

`analyze()` 는 개입지점 없이 `plan.json` 을 내고, `events.py` 가 그 파일을 읽어
`events` 와 `interrupts` 를 채워 다시 쓴다.

**폴백은 두지 않는다.** 사건이 0건이면 개입지점 0이다.
README 의 *"0을 내는 것이 정상 동작이다"* 를 그대로 따른다. `--no-events` 같은 옛 경로도 남기지 않는다.

### plan.json 스키마

추가만 한다. 기존 필드는 유지하므로 `generate.py` 와 `backend/server/tools/seed-from-work.js` 는
수정 없이 돈다.

```
+ events: [{id, what, who, kind, evidence, t}]
+ interrupts[].event_id
+ interrupts[].asked_by      # = event.who. null 가능
+ interrupts[].kind
```

`interrupts[].evidence` 는 이제 사건이 지목한 세그먼트다. 100초 긁기가 아니다.

## 6. 생성자 계약 수정

이걸 같이 하지 않으면 사건이 들어와도 생성자가 무시하고 지금처럼 레벨 1 을 만든다.

`skills/quiz/SKILL.md`:

1. 프롬프트에 사건(`what` · `who` · `kind`)을 넣는다.
2. 활동 유형 표에 `level` 컬럼을 추가한다.

| 레벨 | 유형 |
| --- | --- |
| 1 시각 | 개수 세기 · 색깔 퀴즈 · 모양 찾기 · 같은 것 찾기 · 크기 비교 · 순서 세기 |
| 2 컨텍스트 | 이야기 이해 · 낱말 알기 · 문장 배열 · 마음 읽기 · 도움 주고받기 |
| 3 추론 | 원인과 결과 · 이어질 말 상상 · 내가 그 자리라면 · 안전 알기 |

3. 규칙 추가 — **한 지점에서 레벨 1 만 4개를 만들지 않는다.**
4. 카드 스키마에 `level` 필드 추가. 분포를 집계할 수 있게 한다.

## 7. 검증

| 무엇 | 어떻게 |
| --- | --- |
| 게이트 ①~⑥ | `python3 events.py` 자체검사. 가짜 사건으로 돌며 `claude` 불필요 |
| `snap_forward` | 같은 자체검사. 가짜 정본으로 방향·창 경계 확인 |
| 5편 회귀 | 사건 개수 · 게이트 통과율 · 개입지점 개수 · **`kind` 분포** · **`level` 분포** |
| 눈으로 | `scan.py` 에 사건 트랙 추가. 사건 위치와 스냅된 지점을 같이 그린다 |

**성패 지표는 `kind`·`level` 분포다.** 개입지점 개수가 줄어도 레벨 2·3 이 나오면 성공이다.
현재 기준선: 활동 26건, 레벨 1 편중, 창작형 27%.

## 8. 이번 범위가 아닌 것

- **`kind` 별 점수 가중** — 데이터를 본 뒤에.
- **오디오 덕킹 · 컷 직후 정지** — 개입 방식 확장. 서사 게이트가 풀린 뒤에 값이 난다.
- **캐릭터 이미지 렌더링** — `asked_by` 를 스키마에 싣는 데까지만. 앱에서 누가 어떻게 보이느냐는 별도.
- **act 경계 알고리즘 개선** — 후보 생성에서 빠지므로 당장 급하지 않다.
- **`min_evidence` 를 지점 게이트에서 활동 게이트로 이동** — 사건 경로에서는 `EVENT_MIN_EVIDENCE`
  가 대신하므로 이 이동 자체는 불필요해졌다.

## 9. 알려진 위험

- **사건 추출이 LLM 이다.** 게이트 ①~⑥ 이 최후 방어선이지만, 게이트가 못 잡는 유형
  (사건은 실재하나 유아에게 물을 가치가 없는 것)은 걸러지지 않는다. 검증자 에이전트를
  사건에도 붙일지는 1차 실측 뒤에 정한다.
- **`kind` 다섯 개가 충분한지 모른다.** 5편에서 분포가 한쪽으로 쏠리면 범주를 다시 짠다.
- **20초 창이 근거 없이 정해졌다.** 프레임 창과 맞춘 것이지 아동 발달 근거가 아니다.
  실측에서 스냅 실패가 많으면 먼저 돌릴 눈금이다.
- **`storydot.py` 를 자르는 작업이 기존 `plan.json` 을 깬다.** 재실행이 필요하다.
  전사본은 캐시돼 있어 ASR 은 다시 안 돈다.
- **`EVENT_MIN_EVIDENCE = 2` 는 추측값이다.** 사건당 근거가 몇 개가 정상인지 아직 관측한 적이 없다.
  1차 실행에서 가장 먼저 확인할 분포다.
- **개입지점이 지금(7건)보다 줄 수 있다.** 사건이 있어도 20초 안에 안전한 자리가 없으면 버린다.
  개수가 줄고 레벨이 오르면 성공으로 본다 — 성패 지표를 개수로 잡지 않는 이유다.
